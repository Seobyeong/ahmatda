## 🔴 제품 핵심이 조용히 망가지는 것

### 1. 민감도 슬라이더 한 번에 학습 데이터가 사라짐

- [x] **위치**: `SettingsPanel.tsx:122 handleSensitivityChange`, `OnboardingScreen.tsx:221 handleSensitivityNext`
- **증상**: `applyFeedback`이 `deltaOffset`을 매일 ±1씩 누적하는데, 민감도 변경은 같은 필드에 `SENSITIVITY_DELTA[level]`을 **절대값으로 덮어쓴다.** 2주간 학습해 `-3`이 된 상태에서 민감도를 3→4로 옮기면 `+1`이 되어 4°C가 사라진다. 아무 안내도 없다.
- **왜 심각한가**: 제품 정의서가 "차별점의 본질 = 복사할 수 없는 개인 데이터"라고 쓴 바로 그 데이터를 설정 화면이 지운다.
- **수정 방향**: 기준값(민감도)과 학습값(피드백)을 별도 필드로 분리하고 읽을 때 합산. persist 마이그레이션 필요.

### 2. 알림이 전부 1회성 — 앱을 안 열면 영구히 멈춤

- [x] **위치**: `NotificationService.ts:7` (`RepeatFrequency` import 후 미사용)
- **증상**: 세 알림 모두 일회성 `TimestampTrigger`. 재예약은 `App.tsx`의 effect가 도는 시점, 즉 앱 실행 시에만 일어난다. 알림을 무시하고 앱을 안 연 사용자는 그 뒤로 알림을 영영 못 받는다.
- **수정 방향**: 트리거에 `repeatFrequency: RepeatFrequency.DAILY`.

### 3. 날씨 타임라인이 다른 날 예보를 보여줄 수 있음

- [x] **위치**: `WeatherService.ts:192` — `forecastDate.ts`로 분리하며 수정
- **증상**: `KmaItem`에 `fcstDate` 필드가 아예 없고(`src` 전체에 해당 문자열 없음) `byTime` 맵을 `fcstTime`만으로 키잉한다. 단기예보는 최대 +3일치를 반환하므로 `"1200"` 항목이 여러 번 들어오고 마지막 것이 앞을 덮어쓴다. "오늘 시간대별 날씨" 아래에 내일·모레 값이 뜰 수 있다.
- **수정 방향**: `fcstDate === 오늘`로 필터링한 뒤 맵 구성. `numOfRows: 1000`도 `base_time` 2300일 때 응답을 자르므로 같이 확인.

### 4. 집에 있는데 "외출했다"고 판정

- [x] **위치**: `WifiMonitorService.ts:59`(`checkOnce`), `:98`(리스너), `:108-110`(재확인) — `presence.ts`로 분리하며 수정
- **증상**: `isHome = type === 'wifi' && bssid === homeBssid`. Android는 위치 서비스가 꺼져 있거나 권한이 없으면 BSSID를 `null`로 준다 → `isHome === false` → 집에서 긴급 알림이 뜬다. 10초 재확인도 같은 비교라 오탐을 확인해줄 뿐이다.
- **피해가 세 겹**: ①잘못된 알림 ②`ALERT_DATE_KEY` 소진으로 그날 진짜 알림이 안 옴 ③`recordForgotten`이 실제로 챙긴 항목을 놓침으로 기록해 통계 오염.
- **수정 방향**: `bssid == null`을 "판정 불가"로 분리해 알림을 보내지 않는다.

## 🟠 조건이 맞으면 치명적

### 5. `migrate`가 `undefined`를 덮어써 앱이 매번 크래시

- [x] **위치**: `store/index.ts:574` — *커밋 `5e90bdc`에서 생긴 회귀, `migrations.ts`로 분리하며 수정*
- **증상**: 저장 데이터에 `permanentRoutines`/`checklist` 키가 없으면 `toStringId`가 `undefined`를 그대로 반환하고, migrate가 **그 키를 `undefined`로 만들어 반환**한다. `merge`의 스프레드가 기본값을 덮어쓰고 `buildChecklist`가 매 실행마다 throw한다. migrate 도입 전에는 키가 없으면 기본값이 살아남았다.
- **수정 방향**: `Array.isArray`일 때만 키를 세팅.

### 6. hydration 실패 시 영구 흰 화면

- [ ] **위치**: `AppNavigator.tsx:38`
- **증상**: zustand persist는 `.then()`에서만 `hasHydrated`를 올리고 `.catch()`에서는 아무것도 하지 않는다. AsyncStorage 블롭이 깨지면 `hasHydrated`가 영원히 false → 빈 `View`만 렌더. 렌더가 throw하지 않으므로 `ErrorBoundary`도 안 걸린다. 재설치 외 복구 불가.
- **수정 방향**: `onRehydrateStorage` 에러 경로(또는 타임아웃)에서 hydrated를 올리고 기본값으로 진행.

### 7. 백그라운드 폴링이 어제 체크리스트를 읽음

- [x] **위치**: `WifiMonitorService.ts:63`
- **증상**: `checkOnce`에 `checklistDate === getTodayString()` 검사가 없다. `buildChecklist`는 `DashboardScreen` 마운트나 당겨서 새로고침 때만 돈다. 앱을 안 연 날 15분 폴링이 돌면 어제 항목으로 알림을 보내고, `recordForgotten`이 **어제 라벨을 오늘 날짜로** 기록해 "이번 주 N번 놓침"을 부풀린다.
- **수정 방향**: `checklistDate` 검사 후 필요하면 재빌드.

### 8. iOS에 알림 액션 버튼이 존재하지 않음

- [ ] **위치**: 전역 (`ios:` 블록, `setNotificationCategories()` 모두 없음)
- **증상**: Notifee는 iOS에서 액션 버튼을 쓰려면 카테고리 등록이 필수. 제품 정의서 4.4의 핵심인 피드백 버튼 3개가 iOS에서는 아예 안 뜬다.
- **수정 방향**: `setNotificationCategories()` 등록 + 알림에 `ios: { categoryId }`. 실기기 검증 필요.

### 9. 전날 22:00 알림이 항상 하루를 건너뜀

- [x] **위치**: `NotificationService.ts scheduleDayBeforeAlert`
- **증상**: 형제 함수 둘은 "오늘로 잡고 지났으면 내일" 패턴인데 이것만 무조건 `+1일`. 월요일 09:00에 온보딩하면 월요일 밤이 버려진다.

## ✅ 검증했는데 문제 없던 것

라인 단위로 대조해 정상 확인. **다시 의심하지 말 것.**

- **`utils/kmaGrid.ts`** — 람베르트 정각원추 변환. `sn`·`sf`·`ro`·`theta` 랩어라운드, `floor(x+0.5)`, `XO=43`/`YO=136` 모두 기상청 레퍼런스와 일치
- **`utils/forgotten.ts`** — 7일 창 경계(`age < 0 || age >= windowDays`), ms 델타에 `Math.round`를 써서 DST 영향 없음
- **`utils/temperature.ts`** — 수식 정상
- **`WeatherService`의 `base_time` 계산** — 00:00~00:09→어제 2300, 02:09→어제 2300, 02:10→0200, 10:39→0900, 10:40→1000 전부 정확
- **캐시 오염 없음** — 실패 경로에서 캐시를 쓰지 않음
- **`DashboardScreen` 마운트 effect** — hydration 전 값을 읽는다는 의심이 있었으나, `AppNavigator.tsx:38`이 `useStoreHydrated()`로 렌더를 막아서 안전. 재빌드 effect의 의존성 배열도 정상(`disabled*` 배열은 실제로 바뀔 때만 identity가 바뀜)

직접 구현한 수학·시간 로직이 가장 튼튼하다. 문제는 대부분 **모듈 간 경계**(설정↔학습, 알림↔체크리스트, Wi-Fi↔권한)에 몰려 있다.
