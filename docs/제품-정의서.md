# 아맞다 — 제품 정의서

> 지금까지 개발된 내용을 기준으로 정리한 앱의 정체·기능·방향성 문서.
> 기준일: 2026-09-09 / 기준 커밋: `18d3b0b`
> 관련 문서: [모두의창업 도전신청서](모두의창업-도전신청서.md), `legal/` (개인정보처리방침·스토어 설문지)

---

## 1. 한 줄 정의

**아맞다**는 오늘의 날씨·일정·기기 상태를 읽어 챙길 것을 자동으로 정리하고, **집을 나서는 순간**에 아직 안 챙긴 것을 알려주는 외출 준비 앱이다.

이름 그대로, 지하철에서 뒤늦게 나오는 "아, 맞다!"를 현관 앞에서 먼저 말해주는 것이 목표다.

---

## 2. 풀려는 문제

| 문제 | 기존 도구의 한계 |
|---|---|
| 매일 챙길 것이 날씨·일정에 따라 달라진다 | 할일/메모 앱은 사용자가 **매번 직접 판단해서 적어야** 한다 |
| 정작 나갈 때 앱을 열지 않는다 | 리마인드가 **사용자가 앱을 여는 것**을 전제로 한다 |
| 같은 날씨도 사람마다 다르게 느낀다 | 날씨 앱은 "체감 12°C"라는 **같은 숫자를 모두에게** 보여줄 뿐이다 |

세 번째가 이 앱이 최종적으로 겨냥하는 지점이다. 날씨 데이터는 전 국민에게 동일한 값이지만, 그 값에 대한 반응은 개인마다 다르다. **기준 자체를 개인화하는 것**이 제품의 장기 방향성이다.

---

## 3. 제품 원칙

앞으로의 모든 기능 판단에 적용되는 우선순위.

1. **속도·간편함 > 정교함.** 나가기 직전 몇 초 안에 확인하는 앱이다. 조금의 딜레이도 "확인하기 귀찮음"으로 이어진다. 체크 토글은 애니메이션 완료를 기다리지 않고 즉시 반영하고, 항목 추가는 연속 입력이 끊기지 않게 키보드를 유지한다.
2. **사용자가 입력하는 것이 아니라 확인만 한다.** 목록은 앱이 만들고, 사용자는 승인·수정만 한다.
3. **알림은 시각이 아니라 상황에 맞춘다.** 이미 집을 나선 뒤의 알림은 가치가 급감한다.
4. **광고는 넣지 않는다.** 이 앱의 핵심 가치인 "빠르게 확인된다"와 정면으로 충돌하기 때문에, 수익 모델 검토 단계에서 먼저 배제했다.
5. **모든 자동 판단은 사용자가 덮어쓸 수 있어야 한다.** 자동 감지된 목적은 수동 변경 가능하고, 자동 생성된 항목은 영구적으로 끌 수 있다.

## 4. 현재 구현된 기능 (동작 확인됨)

### 4.1 체크리스트 — 4계층(tier) 구조

체크리스트는 매일 4개 출처에서 자동 조립된다. 출처가 다르면 삭제·복원 동작도 달라야 하기 때문에 tier로 구분한다.

| tier | 이름 | 출처 | 삭제 시 동작 |
|---|---|---|---|
| 0 | 오늘만 | 사용자가 그날 직접 추가 | 그냥 사라짐 |
| 1 | 날씨 알림 | 기상청·에어코리아 데이터 트리거 | `disabledWeatherItems`에 기록 → 영구 비활성 |
| 2 | 목적 준비물 | 오늘의 외출 목적 | `disabledPurposeItems`에 `목적:라벨`로 기록 → 해당 목적에서만 영구 비활성 |
| 3 | 일상 루틴 | 사용자 등록 루틴 (기본: 집 열쇠·지갑·에어팟) | 루틴 목록에서 제거 |

- **재빌드 시 체크 상태 보존** — 목적 변경·날씨 갱신으로 목록이 다시 만들어져도 이미 체크한 항목의 상태는 라벨 기준으로 유지된다.
- **요일별 루틴** — 루틴마다 나타날 요일을 지정할 수 있다(예: 헬스장 카드는 월·수·금). 7일 전부 선택은 "매일"로 정규화한다.
- **자동 재빌드** — 날씨·목적·설정이 바뀌면 체크리스트가 스스로 다시 조립된다.

### 4.2 날씨 연동 — 기상청 + 에어코리아

- **기상청 단기예보 API**: 초단기실황(현재 기온·습도·풍속·강수형태)과 단기예보(3시간 간격 5구간 타임라인: 오전/정오/오후/저녁/밤)를 조회한다. 발표 시각 규칙(실황 매시 40분, 예보 02·05·08·11·14·17·20·23시 + 10분 지연 버퍼)을 반영한 base_time 계산, 위경도 → 격자(nx, ny) 변환을 직접 구현했다.
- **에어코리아 대기질 API**: 시도 단위 PM10/PM2.5 등급 중 나쁜 쪽을 대표값으로 쓴다.
- **체감온도 계산**: `실제기온 + 습도보정 + 바람보정 + Δt(개인 보정치)`. UI에 수식을 그대로 노출해 왜 이 값이 나왔는지 보여준다.
- **날씨 → 준비물 트리거**: 비 예보 → 우산, 미세먼지 나쁨 → 마스크, 폭염 → 물병.
- **예외 처리**: 30분 캐시, 서비스키 미설정·API 실패 시 캐시 폴백, 국내 서비스 지역 밖(`weatherOutOfArea`)일 때 조회를 시도하지 않고 안내 문구를 띄운다.

### 4.3 목적 자동 감지 — 캘린더 연동

오늘 일정 제목에서 키워드를 읽어 5개 목적 중 하나를 자동 선택하고, 목적별 준비물과 옷차림 힌트를 붙인다.

| 목적 | 기본 준비물 |
|---|---|
| 출근·비즈니스 | 노트북, 명함, 충전기 |
| 운동·헬스 | 운동복, 텀블러, 수건, 헬스장 카드 |
| 공부·카페 | 노트북, 노트·펜, 이어폰, 보조배터리 |
| 데이트·약속 | 향수, 보조배터리, 현금 |
| 여행·나들이 | 여권·신분증, 보조배터리, 상비약, 카메라 |

- **선택 기준**: 출발 시각 이후 가장 가까운 일정을 우선하고, 이미 지난 일정은 뒤로 보낸다. 감지 로직과 화면에 표시되는 근거 이벤트가 어긋나지 않도록 정렬 기준을 공유한다.
- **커스텀 키워드**: 설정 화면에서 목적별로 키워드를 추가·삭제할 수 있다(기본 키워드는 읽기전용 칩, 커스텀은 탭해서 삭제).
- **근거 표시**: 자동 감지된 항목에는 "09:00 '팀 회의' 연동됨" 형태의 뱃지가 붙는다.

### 4.4 알림 — 4개 채널

| 시점 | 내용 |
|---|---|
| 전날 22:00 | "내일 08:15에 외출 예정" 사전 안내 |
| 출발 30분 전 | "체크리스트 N개 확인하세요" (탭하면 체크리스트로 딥링크 스크롤) |
| **집 Wi-Fi 이탈 시** | "아직 안 챙긴 것이 있어요" — 미체크 항목 최대 3개 + 나머지 개수 |
| 당일 20:00 | 착장 피드백 — 알림 액션 버튼 3개(추웠음/적당함/더웠음)로 앱을 열지 않고 응답 |

- Doze 모드 대응(`allowWhileIdle`), Android 12+ 정확한 알람 권한 상태 확인 및 설정 화면 유도.
- 미체크 개수가 바뀌면 예약된 출발 알림 문구를 갱신한다(개수만 구독해서 불필요한 재예약을 막음).
- 콜드스타트(앱 완전 종료 상태에서 알림 탭)까지 별도 처리.

### 4.5 Wi-Fi 이탈 감지 — 핵심 차별 기능

집 Wi-Fi BSSID를 등록해두고, 그 네트워크를 벗어나는 순간을 "외출"로 판정한다.

- **오탐 방지**: 10초 디바운스 후 재확인 — 일시적 끊김은 무시.
- **배터리 보호**: 감시는 출발 시각 기준 창(30분 전 ~ +2시간)에서만 동작하고, 2시간 후 자동 종료된다.
- **매일 재arm**: 긴 타이머는 백그라운드에서 조용히 죽을 수 있어, 5분 주기 재확인 + 앱 포그라운드 복귀 시 재확인으로 스스로 회복한다.
- **중복 방지**: 세대 번호(generation)로 리스너 중복 설치를 막고, 날짜 키로 하루 1회만 알린다. 백그라운드 폴링(`react-native-background-fetch`, 최소 15분)과 동일한 dedup 키를 공유해 이중 알림을 방지한다.
- **한계(의도적)**: 앱을 완전히 스와이프 종료하면 폴링도 멈춘다. headless task + persist rehydration 우회 설계가 필요해 현재 범위에서 제외했다.

### 4.6 개인화 학습 — 1차 버전

| 기능 | 동작 |
|---|---|
| **체온 민감도** | 온보딩에서 5단계 선택 → 초기 Δt(-2 ~ +2°C) |
| **일일 피드백** | 저녁 알림에서 추웠음/적당함/더웠음 응답 → Δt ±1°C 조정. 같은 날 재선택 시 이전 보정치를 먼저 되돌려 중복 적용을 막고, 앱 재시작 후에도 유지되도록 `todayFeedback`을 저장한다. 최근 90건까지 보관. |
| **자주 까먹는 항목** | 외출 감지 시점의 미체크 항목을 기록 → 최근 7일간 2회 이상 놓친 항목에 **"이번 주 N번 놓침"** 뱃지. 30일치 보관. |

이 세 가지가 장기 방향인 "개인 기준 학습"의 출발점이다. 특히 놓침 학습은 **사람마다 반복해서 까먹는 물건이 다르다**는 사실을 이미 제품 안에 반영하고 있다.

### 4.7 입력 UX

- **빠른 추가 + 음성 입력**: 마이크 버튼으로 항목을 말해서 추가(`expo-speech-recognition`, ko-KR). 인식 에러 유형별 처리, 연속 추가 시 키보드 유지.
- **즉시 반응 토글**: 체크 애니메이션 완료를 기다리지 않고 상태를 먼저 바꾼다.
- **진행률 바 · 전체해제/모두완료**.

### 4.8 온보딩 (3단계)

1. **권한** — 캘린더 / 알림 / 위치 / 정확한 알람. 각 항목에 "나중에 설정에서 허용 가능" 안내가 있고, **거부 후 설정 화면에서 재요청하는 경로**까지 구현했다(OS가 앱 내 재요청 다이얼로그를 다시 띄워주지 않기 때문).
2. **체온 민감도** — 초기 Δt 결정.
3. **외출 시간 + 집 Wi-Fi 등록** — 현재 연결된 Wi-Fi 자동 감지, 실패 시 직접 입력.

### 4.9 설정

출발 시각 편집(완료 버튼을 누를 때만 커밋), 체온 민감도 재조정, 홈 Wi-Fi 재등록, 내 루틴 관리(추가/삭제/요일 지정), 날씨·목적별 준비물 켜고 끄기, 목적별 자동감지 키워드 관리, 캘린더 권한 재요청.

## 5. 기술 스택

### 5.1 언어

| 언어 | 어디에 |
|---|---|
| **TypeScript** (strict) | 앱 코드 전부 — `src/` 약 5,000줄. `tsc --noEmit` 클린 통과 |
| **Kotlin** | `android/app/src/main/java/com/ahmatda/MainActivity.kt`, `MainApplication.kt` |
| **Swift** | `ios/ahmatda/AppDelegate.swift` |
| **Gradle (Groovy)** | Android 빌드·서명 설정 |

네이티브 3종은 Expo가 생성한 얇은 진입점 셸이고, 직접 손댄 것은 서명 설정과 번들 ID 정도다. **제품 로직은 100% TypeScript.**

### 5.2 프레임워크 · 런타임

- **React Native 0.86** + **React 19.2.3**
- **Expo SDK 57 — Bare Workflow**: `android/`, `ios/` 폴더가 실제로 존재해 네이티브를 직접 수정할 수 있는 형태. Notifee·background-fetch·calendar-events처럼 Expo Go에서 동작하지 않는 네이티브 모듈이 핵심 기능이라 이 선택이 사실상 강제됐다.
- **New Architecture 활성화**(`newArchEnabled=true`) + **Hermes** 엔진 (Android·iOS 양쪽)
- **Metro** 번들러, **Babel**(`babel-preset-expo` + `module-resolver`로 `@/` → `./src` 별칭)

### 5.3 상태 관리 · 화면

| 용도 | 선택 |
|---|---|
| 전역 상태 | **Zustand 5** — 단일 스토어(`src/store/index.ts`) |
| 영속화 | Zustand `persist` 미들웨어 + **AsyncStorage** |
| 화면 전환 | **React Navigation 7** (native-stack) — 온보딩/대시보드 2화면뿐이라 최소 구성 |
| 아이콘 | **lucide-react-native** + **react-native-svg** |

Zustand를 쓴 이유는 보일러플레이트가 거의 없다는 점 외에, **모듈 레벨에서 `useAppStore.getState()`로 접근 가능**하다는 점이 컸다. 알림 백그라운드 핸들러나 Wi-Fi 감시 서비스처럼 React 컴포넌트 밖에서 스토어를 읽고 써야 하는 코드가 많아 여기서 실질적인 이득이 있었다.

**상태 저장 범위**: 체크리스트·루틴·설정·피드백/놓침 이력만 persist한다. `userSettings`는 기본 merge가 얕은 병합이라 신규 필드가 `undefined`로 남는 문제가 있어 한 겹 더 깊게 병합한다.

### 5.4 네이티브 기능 모듈

기능별로 어떤 모듈이 붙어 있는지가 이 앱의 성격을 가장 잘 보여준다.

| 기능 | 모듈 |
|---|---|
| 로컬 알림 · 트리거 · 액션 버튼 | **@notifee/react-native** |
| Wi-Fi BSSID 조회 · 연결 감시 | **@react-native-community/netinfo** |
| 백그라운드 폴링 | **react-native-background-fetch** |
| 캘린더 일정 읽기 | **react-native-calendar-events** |
| 위치(위경도) | **expo-location** |
| 음성 입력 | **expo-speech-recognition** (ko-KR) |

알림에 `expo-notifications` 대신 Notifee를 쓴 것은 피드백 알림의 **액션 버튼 3개**(추웠음/적당함/더웠음), Doze 모드 대응(`allowWhileIdle`), Android 채널 세분화가 필요했기 때문이다.

### 5.5 외부 데이터 — 백엔드 없음

- **기상청 단기예보 API** (초단기실황 + 단기예보), **한국환경공단 에어코리아 대기질 API**
- 통신 **axios**, 날짜 처리 **dayjs**
- API 키: `EXPO_PUBLIC_KMA_API_KEY`, `EXPO_PUBLIC_AIRKOREA_API_KEY` — 미설정 시 전부 안전하게 폴백한다.

**서버가 없다.** 공공 API를 앱에서 직접 호출하고 결과는 AsyncStorage에 30분 캐시한다. 사용자 데이터(체크리스트, 피드백 이력, 놓침 기록, 집 Wi-Fi BSSID)는 전부 기기 안에만 있고 외부로 나가지 않는다. 서버 운영 비용이 0이라는 점과, 개인정보처리방침·데이터 안전성 설문을 훨씬 단순하게 쓸 수 있다는 점이 부수 효과다.

위경도 → 기상청 격자(nx, ny) 변환과 발표 시각(base_time) 계산은 라이브러리 없이 `src/utils/kmaGrid.ts`에 직접 구현했다.

### 5.6 테스트 · 빌드

- **Jest**(`jest-expo` 프리셋) — 순수 함수 중심 유닛테스트: `time`, `temperature`, `kmaGrid`, `sido`, `forgotten`, `purposes`
- 전역 **ErrorBoundary**
- **EAS Build**(클라우드) — `development` / `preview`(APK) / `production`(AAB, 로컬 키스토어 서명) 3개 프로필. macOS가 없어 iOS 빌드에는 사실상 필수 선택이었다.
- Android: Gradle + 업로드 키스토어 서명 / iOS: CocoaPods

## 6. 방향성 — 앞으로 만들 것

### 6.1 개인 기준 학습으로의 확장 (핵심)

지금은 Δt 보정과 놓침 뱃지 수준이지만, 목표는 **"나에게 12도는 추운 날인가"를 앱이 아는 것**이다.

- 저녁 3초 하루 리뷰를 그날의 실제 체감온도와 함께 기록 → 같은 12°C에서도 사람마다 다른 추천
- 우산을 권하는 **강수확률 기준선**, 마스크를 권하는 **미세먼지 기준선**을 항목별로 개인화
- 계절 전환기 재보정

이 방향의 방어력은 기능이 아니라 데이터에 있다. 기능 목록은 복사할 수 있어도 **"이 사람에게 몇 도가 추운지"는 그 사람이 몇 주간 남긴 응답으로만 생긴다.**

### 6.2 알림 트리거 확장 — "문을 열기 전에 잡는다"

| 단계 | 트리거 | 상태 |
|---|---|---|
| 1차 | 출발 시각 전 알림 | 구현 완료 / 실제 출발 시각 학습으로 개인 보정은 예정 |
| 2차 | **충전기 분리 감지** | 예정 — 나갈 준비를 시작했으면서 아직 집 안에 있는 거의 유일한 신호 |
| 최종 | 집 Wi-Fi 이탈 | 구현 완료 — 이미 한 번 놓쳤다는 뜻이지만 30초면 돌아갈 수 있는 마지막 안전망 |
| 확장 | **머무른 뒤 이동 감지** | 예정 — 카페·도서관·강의실 등 집이 아닌 곳까지 커버. 사전 등록 불필요 |

Wi-Fi와 위치는 경쟁이 아니라 역할 분담이다. **Wi-Fi는 집에서 가장 빠르게, 머무름 감지는 조금 늦는 대신 모든 장소를.** 머무름 감지는 위치를 계속 추적하는 대신, 머물렀다고 판단된 지점에만 그때그때 반경을 잡고 OS가 이탈 시점에 앱을 깨우는 방식으로 설계했다.

> 리스크: 백그라운드 위치 권한은 Google Play 심사에서 별도 신청서와 사용 이유 영상을 요구하며 반려 사례가 흔하다. 충전기 분리 감지는 Android에서는 안정적이지만 iOS는 백그라운드 제약이 커서 축소되거나 대체될 수 있다.

### 6.3 수익 모델 (구상)

**기본 무료 + 프리미엄 구독.** 핵심 기능(날씨 연동 체크리스트, 목적 자동 감지, 나가기 전 알림)은 계속 무료. 구독 영역은 항목별 기준선 개인 학습, 계절 재보정, 기록 리포트, 목적 카테고리 무제한, 가족·룸메이트 공유 체크리스트, 위젯·워치 연동.

구독이 성립하는 근거는 **시간이 지날수록 가치가 커지는 구조**라는 점이다. 일반 유틸리티는 첫날이 가장 유용하지만, 이 앱은 응답이 쌓일수록 정확해진다.

순서상 **수익화보다 유지율 확보가 먼저**다. 재방문율과 알림 반응률이 일정 수준에 오른 뒤 구독을 도입한다.

### 6.4 효과 측정 지표

앱이 이미 놓침 이력을 저장하고 있어 효과를 숫자로 증명할 수 있다.

- 주간 놓침 횟수 감소폭 (핵심)
- 알림을 받고 실제로 체크한 비율
- 재방문율
- 하루 리뷰 응답률, 그리고 "추웠다/더웠다" 응답 비율의 감소 (= 개인 기준이 맞아가는지)
