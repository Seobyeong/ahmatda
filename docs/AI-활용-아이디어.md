# AI 활용도 확장 아이디어

> 기준일: 2026-10-14 / 상태: 아이디어 정리 (1번만 구현 중)
> 관련 문서: [AI 연결 설계](AI-연결-설계.md), [비서 기능 아이디어](비서-기능-아이디어.md), [경로 기억 설계](경로-기억-설계.md)

모든 아이디어에 [AI 연결 설계](AI-연결-설계.md)의 원칙을 그대로 적용한다.
- 핵심 판단은 AI 없이 동작한다.
- 로컬에서 먼저 걸러내고, 남은 것만 AI로 보낸다.
- 한 번 배운 것은 다시 묻지 않는다.
- 사용자는 AI 응답을 기다리지 않는다.

각 아이디어는 두 부분으로 나눠 적었다. **로컬로 되는 부분**(키 없이 지금 구현 가능)과 **AI가 필요한 부분**이다.

## 1. 키워드에 안 걸리는 일정 해석 — **구현 중 (1단계)**

자세한 내용은 [AI 연결 설계](AI-연결-설계.md) 2장. 다른 아이디어들이 그대로 재사용하는 공통 기반을 여기서 만든다. 제공자 인터페이스, 보안 키 저장, 동의, 하루 상한, 결과 캐시가 그것이다.

---

## 2. 붙여넣은 안내문에서 준비물 뽑기 — 우선순위 높음

**상황:** 카톡 공지, 학원 문자, 행사 안내 메일에 "준비물: 수건, 실내화, 개인 컵"처럼 적혀 오는 경우.

- **로컬로 되는 부분:** "준비물", "지참", "챙겨" 뒤에 쉼표로 나열된 목록은 정규식으로 뽑는다. 대부분의 안내문이 이 형식이다.
- **AI가 필요한 부분:** 문장으로 풀어 쓴 안내문("실내에서 신을 신발을 가져오시고…")만 AI로 보낸다.
- **토큰과 지연:** 사용자가 붙여넣거나 공유한 순간에만 호출하고, 입력은 그 텍스트 하나다. 사용자가 직접 요청한 동작이라 짧은 로딩 표시는 괜찮다.
- **개인정보:** 사용자가 직접 고른 텍스트만 보낸다. 다만 안내문에 연락처 등이 섞여 있을 수 있으므로, 보내기 전에 미리보기를 보여준다.
- **진입점:** OS 공유 시트("아맞다로 공유")와 빠른 추가 입력창 붙여넣기. 공유 시트는 네이티브 설정이 필요하다.

## 3. 일정 장소 ↔ 기억한 경로 매칭

**상황:** 캘린더 장소가 "강남 사무실", "본사 7층", "회사"처럼 제각각이라, 경로 기억(Route)의 목적지와 바로 연결되지 않는 경우.

- **로컬로 되는 부분:** `Route.matchKeywords`와 문자열 포함 여부로 먼저 매칭한다(경로 기억 설계 3장).
- **AI가 필요한 부분:** 매칭에 실패한 장소 문자열과 등록된 경로 이름 목록(몇 개뿐)만 보내서 "어느 경로인지 / 해당 없음"을 고르게 한다.
- **토큰:** 수락하면 그 장소 문자열을 `matchKeywords`에 추가한다. 1번과 같은 "학습 승격" 구조다.
- **전제:** 경로 기억 2단계(경로 등록)가 먼저 구현돼야 한다.

## 4. 일정 메모를 활용한 해석 (선택적 확장)

**상황:** 제목은 "워크숍"뿐이지만 메모에 "드레스코드: 정장, 노트북 지참"이 적혀 있는 경우.

- **로컬로 되는 부분:** 2번의 "준비물:" 정규식을 일정 메모에도 그대로 적용한다. 이건 외부 전송이 없다.
- **AI가 필요한 부분:** 메모를 AI로 보내는 건 **보내는 데이터가 제목에서 메모로 넓어지는 것**이라, 동의를 따로 받는 별도 옵션으로만 둔다. 기본값은 끔.
- **판단:** 로컬 정규식만으로도 가치가 있으므로 로컬 부분을 먼저 한다.

## 5. 반복되는 '해당 없음' 일정으로 새 목적 제안

**상황:** "PT", "필라테스 2:1", "도수치료"처럼 기존 5개 목적에 안 맞는 일정이 자주 반복되는 경우.

- **로컬로 되는 부분:** AI 결과 캐시에서 목적이 null인 항목이 몇 번 반복되는지 센다.
- **AI가 필요한 부분:** 반복되는 제목 묶음에 이름과 기본 준비물을 붙여 "새 목적 만들기"를 제안한다. 한 달에 한 번 정도면 충분하다.
- **전제:** 사용자가 목적을 직접 만들 수 있는 기능이 먼저 있어야 한다. 지금 목적은 5개로 고정돼 있다.

## 6. 음성 빠른 추가의 여러 항목 분리

**상황:** 음성으로 "우산이랑 도시락이랑 충전기"라고 말하면, 지금은 한 항목으로 통째로 들어간다.

- **로컬로 되는 부분:** 쉼표와 "그리고"로 나누는 것은 안전하다. 하지만 조사 "랑", "하고"로 나누는 것은 "사랑 노트" 같은 오분리가 생겨 로컬만으로는 위험하다.
- **AI가 필요한 부분:** 조사로 이어진 문장만 AI로 나눈다. 다만 사용자가 말한 직후라 **기다림이 생긴다.** 그래서 먼저 한 항목으로 추가해 두고, 나중에 "3개로 나눌까요?" 제안으로 덧붙이는 방식이어야 원칙에 맞는다.
- **판단:** 가치 대비 복잡도가 높다. 2번 이후로 미룬다.

## 7. 사진으로 준비물 확인 (먼 후보)

**상황:** 가정통신문이나 초대장 사진에서 준비물을 뽑는 경우.

- 이미지 입력은 토큰이 텍스트보다 훨씬 많다. 사용자가 직접 찍은 순간에만 호출할 수 있다.
- 기기 OCR(텍스트 인식)로 먼저 텍스트를 뽑고 2번 경로로 넘기는 게 토큰 원칙에 맞다. 기기 OCR이 가능한지는 미검증이다.

## 하지 않기로 한 것

| 아이디어 | 이유 |
|---|---|
| "내일 뭐 챙겨?" 대화형 질문 | 답은 로컬 판단에 이미 있다. 이 역할은 나중에 MCP 방향에서 사용자의 AI가 맡는다. |
| 옷차림 문장 개인화 | 체감온도와 학습값으로 이미 로컬에서 하고 있다. 문장을 다듬는 데 토큰을 쓸 이유가 없다. |
| 까먹은 항목 패턴 설명 | "이번 주 N번 놓침" 집계가 로컬로 충분하다. |
| 주간 회고 리포트 | 표시 예산 원칙상 사용자가 읽을 화면을 늘리는 방향이다. |

## 권장 순서

1. **1번** 완성 — 공통 기반 (진행 중)
2. **2번 로컬 부분** + **4번 로컬 부분** — "준비물:" 정규식 추출. 키 없이 가능하고, 2번과 4번이 같은 코드를 쓴다.
3. **2번 AI 부분** — 공유 시트 진입점과 함께
4. **3번** — 경로 기억 2단계 이후
5. 5·6·7번은 사용 데이터를 보고 다시 판단
