# 외출 감지 재설계 — [떠나기] 버튼 · 능동 알림 · 자기 전 설정 시간

> 기준일: 2026-11-03 / 상태: **결정 확정, 구현 진행 중**
> 관련 문서: [비서 기능 아이디어](비서-기능-아이디어.md), [경로 기억 설계](경로-기억-설계.md), [코드리뷰 펀치리스트](코드리뷰-펀치리스트.md)

## 0. 목표

1. 잠금화면에서 오늘 체크리스트가 보인다.
2. 나가기 전에 **[떠나기]** 를 누르면 남은 것을 짧게 한 번 보여준다.
3. [떠나기]를 안 눌렀든 눌렀든, **안 챙긴 게 남은 채로 나간 게 감지되면** 앱이 먼저 알린다.
4. 사용 초반에 **매일 자기 전, 사용자가 정한 시각**에 내일 챙길 것과 알림 성향을 맞춘다.
5. 알림을 자주 받길 원하는 사람에게는 **집 밖 장소에서 머물다 떠날 때**도 알린다.

## 1. 확정된 결정 (2026-11-03, 다시 논의하지 않음)

| # | 질문 | 결정 |
|---|---|---|
| 1 | [떠나기]를 누른 뒤 안 챙긴 게 남은 채로 나가면? | **그래도 알린다.** [떠나기]는 알림을 끄는 버튼이 아니라 "마지막 확인" 버튼이다. |
| 2 | 외출 확인 신호 | **걷기 감지 + 위치 감지가 주 신호**, Wi-Fi는 정확도를 높이는 **부가 검증**. |
| 3 | 자기 전 설정 시간 알림 | **22:00 전날 알림과 20:00 착장 피드백을 둘 다 대신한다.** |
| 4 | 집 밖 장소에서 머물다 떠날 때 알림 | **선택권을 주되 위치 '항상 허용'을 권장**한다. |

### 바뀌는 기존 결정
- 경로 기억 설계 5장 / 아이디어 문서 "하지 않을 것"의 **"외출 중 위치 계속 기록 안 함"** → 결정 4로 **옵트인(권장) 백그라운드 위치**로 완화한다. 계속 기록하는 게 아니라 "머묾 → 이탈" 판정에만 쓰고 좌표 이력은 저장하지 않는다 (8장).
- 9/16 "Wi-Fi BSSID 이탈 감지가 모든 면에서 빠르다, 위치는 집 밖 장소에만" → 결정 2로 **위치가 주 신호**가 된다. 다만 위치 이탈은 수십 초~수 분 늦으므로, **Wi-Fi 이탈은 "후보" 신호로 먼저 받아 두고** 걷기/위치 확인이 붙는 순간 바로 알린다 (3장). 결과적으로 알림이 Wi-Fi 단독보다 크게 늦지 않으면서 오탐이 줄어든다.
- 9/16 "20:00 고정 대신 귀가 시점 질문" 제안 → 결정 3으로 **사용자가 정한 자기 전 시각** 하나로 통일.

## 2. [떠나기] 버튼

**놓는 곳**
- 앱 대시보드 (1단계)
- 잠금화면 출발 상태 알림의 액션 버튼 — Android (1단계)
- Android 홈 위젯 — 앱을 `ahmatda://leave` 딥링크로 여는 방식 (2단계)
- iOS — 알림 액션은 펀치리스트 #8 결정 대기, 위젯/Live Activity는 macOS 확보 후

**누르면**
1. 오늘 [떠나기]를 눌렀다고 기록한다 (`leaveIntent: { date, at }`).
2. 남은 것이 있으면 **"마지막 확인" 알림**을 띄운다 — 헤드업, 10분 뒤 자동으로 사라짐, 액션 [다 챙겼어요].
   남은 것이 없으면 "다 챙겼어요, 다녀오세요" 토스트 + 출발 상태 알림 정리.
3. 외출 감지에 **"본인이 나간다고 말함"** 신호로 쓴다 — 확인 신호 하나만 붙으면 바로 외출로 판정 (3장).

**누른 뒤 나갈 때 (결정 1)**: 그 시점에도 안 챙긴 게 있으면 긴급 알림을 보낸다. [다 챙겼어요]를 눌렀으면 다 챙긴 상태라 자연히 안 울린다.

## 3. 외출 판정 — 신호 조합

| 신호 | 역할 | 지연 | 비용 |
|---|---|---|---|
| **걷기 시작** (Android Activity Recognition Transition / iOS CMMotionActivity) | 주 신호 | 수 초~1분 | 신체 활동 권한. 네이티브 모듈 필요 (Expo에 없음 — v57 문서 확인 필요) |
| **위치 이탈** (집 지오펜스 / 이동 거리) | 주 신호 | 수십 초~수 분 | 위치 권한. 백그라운드는 '항상 허용' |
| **집 Wi-Fi 이탈** (BSSID) | 부가 검증 · 빠른 후보 | 10초 디바운스 | 없음 (구현됨) |
| [떠나기] 누름 | 의도 신호 | 즉시 | 없음 |
| 학습한 평소 출발 시각 | 사전 확률 | — | 없음 |

**판정 규칙 (초안, 구현 시 테스트로 고정)**
- **외출 확정** = 주 신호 2개 (걷기 + 위치 이탈)
  **또는** 주 신호 1개 + 부가 신호 1개 (Wi-Fi 이탈 또는 [떠나기])
- **오탐 거르기**: Wi-Fi만 끊기고 걷기·위치가 없으면 외출 아님 (공유기 재부팅, Wi-Fi 직접 끔, 방 구석 약전계).
- 신호들은 **10분 창 안에서** 모였을 때만 묶는다. 오래된 신호는 버린다.
- 판정 로직은 `services/departure/decide.ts` 순수 함수로 분리하고 테스트를 같이 쓴다 (기존 `presence.ts` 원칙).

**권한별 저하 동작**
| 허용된 권한 | 동작 |
|---|---|
| 걷기 + 위치 '항상' | 위 규칙 그대로 |
| 걷기 + 위치 '사용 중' | 집에서는 걷기 + Wi-Fi로 판정. 집 밖 장소 알림은 없음 |
| 걷기 없음 | 위치 + Wi-Fi (지금보다 느리지만 정확) |
| 둘 다 없음 | 지금처럼 Wi-Fi 단독 |

## 4. 집 밖 장소에서 머물다 떠날 때 (결정 4)

- **설정:** 알림 성향이 "자주"이거나 사용자가 켰을 때만. 켤 때 위치 '항상 허용'을 권장하는 안내 화면을 거친다 (Google Play "눈에 띄는 공개" 요건을 겸함).
- **iOS:** 방문(Visits) 모니터링 — 머문 장소·떠난 시각을 저전력으로 받음.
- **Android:** 방문 API가 없음 → 걷기 감지가 멈춘 채 일정 시간(기본 20분) 지나면 그 자리에 지오펜스를 걸고, 이탈 + 걷기 시작이면 판정.
- **알림 내용:** 아침에 체크한 것 중 **꺼내 쓰는 물건**(충전기·우산·텀블러·노트북)만. 없으면 울리지 않는다.
- **알려진 한계:** Android는 앱이 종료되면 지오펜스가 와도 앱이 깨어나지 않는다 (9/16 v57 문서 확인). 걷기 감지 쪽은 매니페스트 리시버로 받을 수 있어 이 한계를 덜 수 있는지 구현 시 확인.

## 5. 자기 전 설정 시간 (결정 3)

- **설정:** `nightlyCheckTime` (기본 22:00, 온보딩 설문에서 받음). 기존 `day-before-alert`(22:00)와 `feedback-alert`(20:00)를 **하나의 `nightly-check` 알림으로 대체**한다.
- **내용:** ① 오늘 어땠는지 (추웠음/적당함/더웠음 — 기존 피드백 액션 유지) ② 내일 챙길 것 확인 ③ 알림 빈도 조정.
- **빈도:** 첫 14일은 매일. 이후에는 물어볼 게 있는 날만 (피드백이 학습을 바꿀 날, 내일 일정·날씨가 평소와 다른 날).
- **자정 넘김:** 00:30에 설정하면 "내일"은 달력상 오늘이다. 그래서 ① 알림 본문에 "내일"을 쓰지 않고 출발 시각만 말하고 ② 알림에서 받은 착장 피드백은 달력 날짜가 아니라 **지금 이전의 가장 최근 출발 시각이 속한 날**에 기록한다 (`getFeedbackOutingDate`).

## 6. 첫 사용 설문

9/16 결정(질문 최소, 나이·성별·직업 묻지 않음)을 지킨다. 답이 곧바로 설정을 바꾸는 질문만.
1. 알림 성향 — 필요할 때만 / 보통 / 자주 (→ 4장 켜짐 여부, 5장 빈도)
2. 자기 전 정리 시각 (→ `nightlyCheckTime`)
3. 주 이동수단 — 대중교통 / 도보·자전거 / 자차 (→ 우산·외투 기준선)

## 7. 잠금화면 표시

- **Android:** 폰 잠금화면 위젯은 OS 차원에서 없음 (Android 5.0에서 제거, 지금은 태블릿 일부만). → 기존 **출발 상태 알림(ongoing)** 에 [떠나기] 액션을 붙여 잠금화면 위젯 역할을 하게 한다. Android 16 Live Updates는 사용 조건과 notifee 지원 여부 **미확인**.
- **iOS:** 잠금화면 위젯(`accessoryRectangular`) 또는 Live Activity. macOS·Apple 계정 확보 후.

## 8. 개인정보·스토어 영향

- 신체 활동 데이터, 백그라운드 위치 → 개인정보처리방침, Play 데이터 안전성, Apple App Privacy **3종 모두 개정**.
- Play Console **백그라운드 위치 권한 신고서 + 시연 영상** 필요.
- 원칙: 좌표·활동 이력은 저장하지 않는다. 판정에 쓰고 버린다. 저장하는 건 "집 좌표"와 "그날 외출 판정 시각"뿐. 기기 밖으로 나가지 않는다.

## 9. 구현 순서

1. ✅ **[떠나기] 버튼** — 대시보드 + 잠금화면 알림 액션, 마지막 확인 알림 (`2fcd0c8`)
2. ✅ **자기 전 설정 시간** — `nightly-check`로 두 알림 대체, 자정 넘김 처리. 남은 것: ① "첫 14일 매일 → 이후 물을 게 있는 날만"(지금은 매일 반복 — 조건 판단에 3단계 설문의 알림 성향이 필요) ② ✅ **다음 외출 준비 미리보기** — 정리 알림 탭/대시보드 버튼으로 열림. 그날 요일·일정·예보로 뜰 항목과 이유, "이 날만 추가"(항목 속성 문서의 특정 날짜 1회 `onDate`). 아침 체크리스트 우산 기준도 미리보기와 같게 맞춤(남은 시간대 강수확률 60%)
3. ✅ **첫 사용 설문** — 3문항 (온보딩 2단계 + 설정 화면). 2026-11-04 결정한 효과:
   - 알림 성향 3단계: **필요할 때만** = 출발 전 알림 없음(이탈 알림·자기 전 정리는 유지) / **보통** = 지금 그대로 / **자주** = 집 밖 머묾 알림 켜짐(7단계에서 구현, 지금은 "준비 중" 표시). 자기 전 정리의 "2주 뒤엔 물을 게 있는 날만"(필요할 때만·보통)은 **아직 구현 전**.
   - 이동수단: **자차** = 우산은 지금 비 올 때만(예보로는 안 넣음, 미리보기도 같음) / **도보·자전거** = 체감온도를 쾌적 구간(18~26°C) 밖에서 1°C 더 극단으로
4. ✅ **판정 로직 순수 함수** (`services/departure/decide.ts`) + 테스트 17개 — 신호 없이 규칙만. 3장 규칙에 더해 확정한 것: 같은 종류 신호는 한 번으로 셈 / 집 복귀 신호(Wi-Fi 재연결·집 반경 재진입) 이전의 이탈·걷기는 무효, [떠나기]는 유지 / [떠나기] 단독은 후보도 아님 / 걷기·위치 둘 다 못 쓰면 Wi-Fi 단독 확정(지금 동작). **안전장치(2026-11-04 결정):** 주 신호를 쓸 수 있는데 안 와도(앱 종료로 신호 유실 등) 집 Wi-Fi 이탈이 **5분** 동안 복귀 없이 이어지면 확정. 10분 창과 무관하게 2시간 안의 마지막 Wi-Fi 상태를 본다
5. **걷기 감지 네이티브 모듈** (Android 먼저) — v57 Expo Modules 문서 확인 후
6. **위치 신호** — 집 지오펜스, 권한 단계별 저하 동작
7. **집 밖 장소 머묾 → 이탈** — 옵트인 안내 화면 포함
8. 홈 위젯 [떠나기], 개인정보 문서 3종 개정

각 단계는 실기기 미검증 상태로 커밋되며, 타이머·스케줄링이 들어가는 2·4~7단계는 커밋 전 코드 리뷰를 돌린다.
