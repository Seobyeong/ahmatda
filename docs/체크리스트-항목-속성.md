## 1. 원칙

할 일 앱의 속성(우선순위·마감일·장소)을 그대로 가져오지 않고, **챙길 물건에 맞게 바꾼다.** 제품 원칙 1(속도·간편함)과 2(사용자는 입력하지 않고 확인만)를 지키기 위해서다.

| 할 일 앱 | 아맞다 | 이유 |
|---|---|---|
| 우선순위 | **"꼭 챙김" 표시** | 물건은 "중요도 2"가 아니라 "놓고 가면 큰일 나는가"로 갈린다 |
| 마감일 | **언제 나타날지** | 물건에는 마감이 없고, 필요한 날이 있다 |
| 장소 | **보관 위치 / 일정 장소 / 위치 알림** | "어디 두었나"와 "어디 갈 때 필요한가"를 나눠서 다룬다 |

## 2. 결정 사항

### 2.1 입력 방식 — 이름만 입력하고, 속성은 나중에
- 항목 추가는 지금처럼 **이름만 치면 바로 추가**된다. 키보드도 유지한다(원칙 1).
- 속성은 항목을 눌러 여는 편집 화면에서 붙인다. **모든 속성은 선택 사항**이고, 기본값만으로도 지금과 똑같이 동작해야 한다.

### 2.2 중요도 — "꼭 챙김" 토글 하나
- 켜면:
  - Wi-Fi 이탈 시 이 항목이 미체크면 알림을 더 강하게 보낸다(문구 앞에 배치, 소리 등 — 세부는 구현 때 정한다).
  - 위젯·잠금화면·워치처럼 표시 예산이 작은 화면에 **먼저 보인다.**
- 자주 까먹는 항목(`forgottenHistory`)은 앱이 "꼭 챙김으로 표시할까요?"를 **제안만** 한다. 자동으로 켜지는 않는다(원칙 5).
- 3단계 우선순위는 쓰지 않는다. 매번 고르는 부담에 비해 얻는 게 적다.

### 2.3 언제 나타날지 — 기존 + 2가지 추가

| 조건 | 상태 | 예시 |
|---|---|---|
| 오늘만 (`temp`) | 있음 | |
| 매일 / 요일 (`days`) | 있음 | 헬스장 카드 — 월·수·금 |
| **특정 날짜 1회** | 추가 | 10/17(금) "반품 택배" — 그날만 나타나고, 날짜가 지나면 사라진다 |
| **일정에 연결** | 추가 | "결혼식"이 들어간 일정이 있는 날 → "축의금 봉투" |

- 기간(시작~끝)은 넣지 않는다.
- **일정 연결은 키워드로 저장한다.** 일정 ID나 일정 제목 원문은 저장하지 않는다. 개인정보처리방침상 캘린더 일정은 기기에도 저장하지 않기 때문이다. 사용자가 적은 키워드와 오늘 일정 제목을 그때그때 비교한다. 목적 감지의 `customKeywords`와 같은 방식이다.
- AI 연결과의 관계: AI 제안 중 "목적 없이 준비물만 있는 제안"(예: 결혼식 → 축의금 봉투)을 수락하면 **일정 연결 항목으로 저장**할 수 있다. 이렇게 하면 AI 문서 5장의 "키워드로 승격할 수 없는 제안"을 처리할 곳이 생긴다(구현 때 연결).

### 2.4 장소 — 세 가지 모두, 단계를 나눠서

| 의미 | 내용 | 비용 | 단계 |
|---|---|---|---|
| **보관 위치 메모** | "현관 서랍", "차 트렁크" 같은 짧은 문구. 체크리스트에서 이름 아래 작게 보인다 | 작음 | 먼저 |
| **일정 장소 연결** | 오늘 일정의 장소 문자열(`CalendarEvent.location`)에 키워드가 들어가면 나타난다. 예: 장소에 "수영장" → "수경". 위치 감지는 필요 없다 | 작음 (2.3 일정 연결과 같은 구조) | 먼저 |
| **위치 도착·이탈 알림** | 지오펜스. 예: 회사를 나설 때 "도시락통". 지금은 집(Wi-Fi 이탈)만 판단한다 | 큼 — 백그라운드 위치 권한, 배터리, 스토어 심사 | **나중** (경로 기억과 함께 검토) |

- 위치 알림은 착수 전에 확인할 것: iOS·Android 지오펜스 등록 수 한도, 백그라운드 위치 권한 심사 기준, Expo v57 `expo-location` geofencing 지원 범위. **전부 미검증이다.**

## 3. 데이터 구조 초안

```ts
interface ChecklistItem {
  // ...기존 필드
  essential?: boolean;     // 꼭 챙김
  storedAt?: string;       // 보관 위치 메모 (짧은 문구)
  onDate?: string;         // "YYYY-MM-DD" — 특정 날짜 1회. 지나면 정리
  eventKeywords?: string[];    // 일정 제목에 이 중 하나가 들어가면 나타남
  locationKeywords?: string[]; // 일정 장소에 이 중 하나가 들어가면 나타남
}
```

- **어디에 저장하나:** 특정 날짜·일정 연결·장소 연결 항목은 "조건이 붙은 루틴"으로 본다. `permanentRoutines`에 넣고, 체크리스트를 다시 조립할 때 조건을 평가한다. 지금 `days`를 평가하는 자리와 같다. 그러면 계정 동기화(`updatedAt`, last-write-wins)도 그대로 적용된다.
- **조건끼리의 관계:** 조건이 여러 개면 **하나라도 맞으면 나타난다(OR).** 조건이 하나도 없으면 매일 나타난다(지금 루틴과 같음). 특정 날짜 1회 항목은 날짜가 지나면 조립 시점에 정리한다.
- **tier 1·2 항목(날씨·목적)의 꼭 챙김과 보관 위치:** 이 항목들은 매번 새로 만들어지므로 항목에 저장할 수 없다. `disabledWeatherItems`·`disabledPurposeItems`처럼 `userSettings`에 라벨 기준으로 둔다. 예: `essentialLabels`, `storedAtByLabel` — 이름은 구현 때 정한다.
- **오늘만(tier 0) 항목:** 꼭 챙김과 보관 위치만 의미가 있다. 나타날 조건은 해당하지 않는다.

## 4. 구현 순서 (제안)

| # | 내용 |
|---|---|
| 1 | 항목 편집 화면(누르면 열림) + 꼭 챙김 + 보관 위치 메모 |
| 2 | 특정 날짜 1회 |
| 3 | 일정 연결 · 일정 장소 연결 (키워드 비교, 같은 편집 UI) — AI 제안 수락 경로와 연결 |
| 4 | 꼭 챙김의 알림 강도·위젯 우선 노출 반영 |
| 5 | 위치 도착·이탈 알림 — 경로 기억 단계에서 별도 검토 |
