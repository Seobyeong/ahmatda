# [메모] 할일·캘린더 앱 전환 장벽 — 인터뷰 확인 전 기록

> 🗒️ **2026-10-07 논의 내용을 저장만 해둔 문서다.** 아직 `01-공감-조사도구.md`에 반영하지 않았다.
> 인터뷰에서 확인한 뒤 1장·2장은 공감 문서로 옮기고, 3장은 4단계 구현 재료로 넘긴다.
> ⚠️ **3장은 해결책이다.** 1~3단계 문서로 옮기지 않는다 (README "이 과제의 특수 조건" 1번).

## 1. 가설 — 사람들은 왜 쓰던 앱을 못 떠나는가

**출발 가설:** 다른 앱을 쓰고 싶어도, 이미 맞춰 둔 앱을 떠나 처음부터 다시 맞추는 과정이 귀찮아서 못 옮긴다.

이 "맞춰 둔 상태"는 두 겹으로 나뉜다. 어느 쪽이 진짜 장벽인지에 따라 결론이 갈린다.

| 층 | 예시 | 성격 |
|---|---|---|
| **데이터** | 일정, 할일 목록, 반복 규칙, 메모 | 옮기기 비교적 쉬움 — 기술 문제 |
| **습관·관계** | 태그 쓰는 방식, 알림 거는 시점, 아침에 목록 훑는 루틴, 가족·회사와 공유 중인 캘린더 | 옮기기 어려움 — 행동 문제 |

- 데이터 층이 장벽이면 → **옮기는 과정을 줄이는 것**이 답
- 습관·관계 층이 장벽이면 → **옮기지 않아도 되게 하는 것**이 답
- 둘 다 아니면 → 애초에 바꾸고 싶은 동기가 약한 것이다. 가설 자체를 버린다.

> 아래 표는 최초 논의 기록이다.

`01-공감-조사도구.md` **B-4 파트 3**의 "휴대폰 알림이나 메모 앱 써보신 적 있어요?" 뒤에 붙일 후보.
규칙 2(의견이 아니라 사건)에 맞춰 **"왜 안 바꾸세요?"가 아니라 "바꾸려다 그만둔 그날"**을 묻는다.

| 질문 | 노리는 것 |
|---|---|
| 지금 일정이나 할 일은 어디에 적어두세요? (앱·종이·안 적음) | 전제 확인 — **아예 안 쓰는 사람**이 얼마나 되는지 |
| 그 앱 쓰신 지 얼마나 됐어요? 그 전엔 뭐 쓰셨어요? | 실제 전환 경험 유무 |
| 다른 앱으로 바꿔보려고 했던 **마지막 때** 얘기해 주세요. 어디까지 하다 그만두셨어요? | 이탈 지점 — 설치만? 옮기다가? 며칠 쓰다가? |
| 그때 옛날 앱에 있던 건 어떻게 하셨어요? | 데이터 층 장벽 여부 |
| 그 캘린더를 같이 보는 사람이 있어요? | 관계 층 장벽 여부 |
| (가능하면) 캘린더 화면 한번 보여주실 수 있어요? | 일정 제목이 실제로 어떻게 적혀 있는지 관찰 ("치과", "ㅁㅁ" 수준인지) |

**답을 읽는 기준**

| 이런 답이 많으면 | 해석 |
|---|---|
| "옮기는 게 일이라서", "다시 다 입력하기 싫어서" | 데이터 층 장벽 |
| "가족이랑 같이 써서", "손에 익어서", "어디 뭐 있는지 아니까" | 습관·관계 층 장벽 |
| "딱히 바꿀 이유가 없어서" | 전환 동기 부족 — 가설 기각 |
| "앱 안 써요, 그냥 기억해요" | 전환이 아니라 **처음 시작**의 문제 — 다른 질문이 필요 |

## 3. 🔒 해결 방향 후보 — 4단계 재료 (1~3단계 문서로 옮기지 않음)

| 방식 | 장점 | 한계 |
|---|---|---|
| **스크린샷 + AI 분석** | API 없는 앱·종이 메모도 됨. "찍기만 하면 정리" 첫인상 | 보이는 것만 읽음(반복 규칙·숨은 메모 누락), 긴 목록은 여러 장, 그 시점에 멈춘 정보, 인식 오류 검수 필요 |
| **기존 앱 데이터 연동** | 정확, 계속 동기화 | 앱마다 개별 구현, API 없는 앱(예: 삼성 리마인더)은 불가 |
| **공존 (옮기지 않음)** | 사용자는 하던 대로, 위에서 "챙길 것"만 판단 | 아맞다만의 가치가 분명해야 함 (4장 2번) |

**현재 생각한 우선순위** (인터뷰 결과로 바뀔 수 있음)

1. 기기 OS 캘린더(·iOS 미리알림)를 **읽기 전용**으로 연결 — 연동 하나로 구글 캘린더 등 기기에 동기화된 것까지 커버
   - ⚠️ 미검증: `expo-calendar` v57에서 읽을 수 있는 범위, Android 할일 저장소 부재 → 구현 전 문서 확인
2. 스크린샷은 연동 안 되는 것(종이 메모, 시간표, API 없는 앱)용 **보조 경로**
3. 습관 층은 옮기지 않고 **과거 일정에서 추론** (예: "화·목 저녁 운동") — 사용자가 설정할 것이 없음

판단 계층 하나 + 표시 계층 여럿, 엔진을 만들지 않고 기존 앱을 활용한다는 기존 원칙과 같은 방향이다.

## 4. 이어서 고민할 문제

1. **연결할 게 없는 사람이 다수일 수 있다.** 타깃(1인가구 등)이 애초에 캘린더·할일 앱을 안 쓰면 이 논의는 소수 얘기가 된다. 그 경우 "전환"이 아니라 **빈 상태에서 첫날부터 쓸모 있게 만드는 것(콜드 스타트)**이 진짜 문제다. → 2장 첫 질문으로 먼저 확인
2. **공존형이면 아맞다의 존재 이유가 흐려진다.** "그냥 원래 앱 알림 쓰면 되지"에 답할 수 있어야 한다. 차별점은 일정을 보고 **챙길 물건을 판단하는 것**인데, 이게 3단계 구상의 핵심 질문과 이어진다.
3. **일정 제목에 판단할 만큼 정보가 있는가.** 실제 캘린더는 "치과", "ㅇㅇ", "회의"처럼 짧다. 추론할 재료가 부족하면 연동해도 할 수 있는 게 적다. → 인터뷰 관찰로 확인
4. **첫인상에서 틀리면 신뢰를 잃는다.** 자동 추론이 첫날 틀리면 "역시 안 맞네"로 끝난다. 추론 결과를 바로 적용하지 않고 **확인받는 단계**가 필요한지.
5. **권한과 개인정보.**
   - 캘린더 전체 읽기 권한은 "준비물 앱"이 달라기엔 크다. 첫 실행 거부율이 높을 수 있다 → 권한을 언제, 어떤 설명과 함께 요청할지
   - 스크린샷을 외부 AI로 보내면 일정·인간관계 정보가 서버로 나간다 → 기기 내 처리 가능성, 처리방침·동의 문구
6. **읽기만 할지, 쓰기도 할지.** 쓰기까지 하면 중복·충돌·원본 오염 문제가 생긴다. 읽기 전용이 기본값으로 안전하다.
7. **떠날 수 있게 해주는 것도 신뢰다.** 내보내기를 열어두면 "갇히지 않는다"는 신호가 된다. 들어오는 장벽을 낮추려는 사람에게 나가는 문도 같이 보인다.
8. **5단계 확인에서 잴 지표.** 연결 권한 허용률, 연결 후 7일 잔존율, 추론 결과 수정 비율 — 지금 정해두면 5단계가 이 가설을 되받을 수 있다.
