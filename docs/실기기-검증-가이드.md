# 실기기 검증 가이드 — 외출 감지 재설계

> 기준일: 2026-11-04 / 대상: Android (iOS는 macOS 확보 후)
> 관련 문서: [외출 감지 재설계](외출-감지-재설계.md) 9장 각 단계의 "실기기에서 확인할 것"을 여기 한 곳에 모았다.
> 결과는 맨 아래 기록표에 적고, 실패한 항목은 재설계 문서 해당 단계에 대책과 함께 옮긴다.

## 0. 준비

**기기:** Android 10 이상 실기기 1대(가능하면 2대 — 삼성 1대 + 다른 제조사 1대. 배터리 최적화가 제조사마다 다르다).
Google Play 서비스가 있어야 한다(활동 인식·지오펜스가 Play 서비스 기능).

**빌드 두 가지 — 목적이 다르다:**

| 빌드 | 명령 | 쓰는 곳 |
|---|---|---|
| 개발 빌드 (Metro 연결) | 기기 USB 연결 → `npx expo run:android` | 화면·흐름 확인, 로그 보기. **앱 종료·재부팅 시나리오에는 부적합** (JS를 PC에서 받아옴) |
| 미리보기 APK | `eas build -p android --profile preview` → 설치 | 백그라운드·앱 종료·재부팅·하루 종일 시나리오. 실제 사용자와 같은 조건 |

네이티브 코드(걷기 모듈·위젯·매니페스트 권한)가 바뀌었으니 **기존 설치본 위에 JS만 갱신하면 안 된다** — 새로 빌드해 설치한다.

**기기 설정:**
- 개발자 옵션 → USB 디버깅 켜기
- 테스트하는 동안은 배터리 최적화를 **기본값 그대로** 둔다 (사용자 조건과 같게). 한 시나리오(S11)에서만 바꿔 본다.

## 1. 진단 화면

설정 패널 제목 **"설정"을 길게 누르면** 진단 화면이 열린다 (개발·미리보기·정식 빌드 모두. 기기 안 정보만 보여준다).

| 항목 | 뜻 |
|---|---|
| 권한 | 위치(사용 중/항상), 신체 활동, 알림 |
| 신호 사용 가능 | 걷기 / 위치(집 지오펜스) — 외출 판정의 `availability` |
| 집 지오펜스 / 머문 장소 지오펜스 | 걸려 있는지, 집 좌표 등록 여부 |
| 신호 기록 | Wi-Fi·집 반경 이탈/복귀 시각 (최근 3시간) |
| 걷기 / 탈것 / 정지 시작 | 네이티브가 기록한 시각 (최근 것부터) |
| 오늘 외출 판정 | `none / candidate / confirmed` + 근거 신호 |
| 알림 보낸 날 | 외출 긴급 알림(`wifi_alert_date`), 외출 확정(`departure_confirmed_date`) |
| 머무는 자리 | 등록 시각·이탈 시각·오늘 보낸 횟수 |
| 외출 흔적 | 외출한 날짜들, 집 Wi-Fi 관찰 시각 |
| 예약된 알림 | notifee 트리거 id 목록 (자기 전 정리 `nightly-check-날짜` 6개 + `nightly-check-tail` 1개가 보여야 함) |

버튼 (누를 때마다 확인을 받는다 — 실제 알림이 갈 수 있다): **지금 판정** (DepartureService.evaluate) /
**머묾 확인** (AwayPlaceService.tick) / **자기 전 계획** (NightlyService.plan) /
**테스트 기록 지우기** — 신호 기록, 걷기·탈것·정지 기록, 오늘 알림 보낸 표시·외출 확정 표시, 머무는 자리·오늘 보낸 횟수,
오늘 [떠나기] 기록을 지우고 Wi-Fi 감시를 다시 건다. **외출 흔적(최근 7일)은 지우지 않는다** (자기 전 정리의 실제 기록).

"지금 판정"이 "확정"이어도 **출발 감시 창 밖이거나 오늘 이미 알림을 보냈으면** 실제 알림은 안 간다 — 같은 화면의 두 줄을 같이 본다.

## 2. 자주 쓰는 adb 명령

```sh
# JS 로그 (개발 빌드)
adb logcat -s ReactNativeJS:V

# 15분 백그라운드 확인을 지금 강제로 실행 — job id는 기기에서 먼저 찾는다 (라이브러리 문서에서 확인 못 함)
adb shell dumpsys jobscheduler | grep -B2 -A6 "com.ahmatda"     # "JOB #u0a123/<id>: ... com.ahmatda/..." 의 <id>
adb shell cmd jobscheduler run -f com.ahmatda <id>

# Doze(잠자기) 강제 진입 / 해제 — 화면 끄고 오래 둔 상황 흉내
adb shell dumpsys deviceidle force-idle
adb shell dumpsys deviceidle unforce

# 예약된 알람 확인 (자기 전 정리·출발 알림)
adb shell dumpsys alarm | grep -A3 com.ahmatda

# 위젯 [떠나기] 위조 시도 — 아무 일도 없어야 정상 (S9)
adb shell am start -a android.intent.action.VIEW -d "ahmatda://leave?n=deadbeef" -n com.ahmatda/.MainActivity

# 재부팅
adb reboot
```

**모의 위치:** 개발자 옵션 → "모의 위치 앱 선택"에 모의 위치 앱을 지정하면 지오펜스 이탈을 앉아서 볼 수 있다.
다만 걷기·정지(활동 인식)는 흉내 낼 수 없어 **실제로 걸어야 한다**. 최종 확인은 모의 위치 없이 한 번 더 한다.

## 3. 시나리오

각 시나리오 시작 전 진단 화면에서 **테스트 기록 지우기**, 출발 시각을 지금부터 10~20분 뒤로 맞춘다(감시 창 = 출발 30분 전 ~ +2시간).
체크리스트에 일부러 안 챙긴 항목을 하나 남긴다.

### S1. 걷기 감지 기초 (5단계)
1. 온보딩 신체 활동 허용 → 진단: 걷기 사용 가능 = 예
2. 집 안에서 1~2분 걷기 → 걷기 시작 시각이 기록되는지 (지연이 얼마인지 메모)
3. 걷다가 앱을 완전히 닫았다 다시 열기 → **재등록 때 새 걷기 시작이 "지금 시각"으로 또 생기는지**
   - 생기면: 기록된 시각이 원래 걷기 시작 시각에 가까운지, 지금 시각인지 적는다 (지금 시각이면 대책 필요 — 재설계 문서 5단계)
4. 가만히 5분 이상 → 정지 시작이 기록되는지 / 버스·지하철을 타면 탈것 시작이 기록되는지

### S2. 집 등록·'항상 허용' 흐름 (6단계)
1. 온보딩 3단계에서 [지금 위치를 집으로 등록] — 실내에서 몇 초 걸리는지, 20초 안에 안 되면 오류 문구
2. '위치 항상 허용' 행 → **공개 안내가 시스템 권한 화면보다 먼저** 뜨는지 (Play 시연 영상에 이 장면이 필요 — 녹화해 둔다)
3. Android 11+ : 시스템 설정 화면으로 넘어가 '항상 허용' 선택 → 돌아오면 체크 표시
4. 진단: 집 지오펜스 = 걸림
5. 한 번 거부 → 다시 누르면 안내부터 다시 (바로 설정으로 가면 안 됨) / 두 번 거부 → 설정 화면으로

### S3. 외출 판정 — 권한 조합별 (6단계)
| 조합 | 하는 일 | 기대 |
|---|---|---|
| 걷기 + 항상 허용 | 집을 걸어 나가 150m 이상 | Wi-Fi 끊김 + 걷기(또는 집 반경 이탈)로 확정 → 긴급 알림. **알림까지 걸린 시간** 메모 |
| 걷기만 (위치 사용 중) | 같은 동작 | Wi-Fi 끊김 + 걷기로 확정 |
| 항상 허용만 (신체 활동 거부) | 같은 동작 | Wi-Fi 끊김 + 집 반경 이탈로 확정 (더 늦음) |
| 둘 다 없음 | 같은 동작 | Wi-Fi 끊김 10초 뒤 즉시 (예전과 같음) |

각 조합에서 진단의 "오늘 외출 판정" 근거 신호를 적는다.

### S4. 현관까지 갔다 돌아옴 (6단계)
걷기 + 항상 허용 상태에서 현관 밖으로 나가 Wi-Fi가 끊기면 1분 안에 돌아와 다시 붙기 → **알림이 오면 실패**.
5분 넘게 있다가 돌아오는 경우는 안전장치로 알림이 가는 게 정상(결정 6).

### S5. 집에서 Wi-Fi만 끔 (6단계, 알려진 동작)
걷기·위치를 쓸 수 있는 상태에서 집 안에서 Wi-Fi를 끄고 가만히 있기 → 5분 뒤 안전장치로 알림이 간다(설계대로).
실제로 몇 분 뒤 오는지 적는다. 너무 거슬리면 재설계 문서에 안건으로 올린다.

### S6. 앱 상태별 (6단계)
같은 외출을 세 상태로 반복: ① 앱 화면 켜 둠 ② 홈 버튼으로 백그라운드 ③ 최근 앱에서 스와이프해 종료.
- ③은 문서상 지오펜스로 앱이 안 깨어난다. 그래도 알림이 오는지, 온다면 무엇으로 왔는지(진단 근거 신호) 적는다.
- 미리보기 APK로 한다.

### S7. 재부팅 (5·6단계)
재부팅 후 앱을 열지 않은 채: ① 걷기 기록이 계속 쌓이는지(부팅 리시버) ② 집 지오펜스가 다시 걸리는지(진단) — 열지 않으면 진단을 못 보므로,
재부팅 → 30분 뒤 외출 → 알림이 오는지로 판단한 뒤 앱을 열어 진단 확인.

### S8. 집 밖에서 머물다 떠날 때 (7단계)
설정에서 '집 밖에서 떠날 때 알림' 켜기, 아침 체크리스트에서 충전기·우산 같은 꺼내 쓰는 물건을 체크.
1. 카페·사무실에 25분 이상 앉아 있기 → 진단: 머무는 자리 등록 (등록까지 걸린 시간 — 폴링 간격만큼 늦다)
2. 일어나 걸어서 떠나기 → "두고 가는 거 없나요?" 알림, 체크한 물건만 나오는지
3. 같은 곳에서 화장실만 다녀오기 → 알림이 오면 실패
4. 차로 떠나기 → 알림 없음이 정상
5. **지하철·버스 25분 이상** → 중간에 머무는 자리가 잡히는지 (잡히면 내릴 때 알림 — 기록해 둔다)
6. 하루에 네 곳 → 세 번째까지만 알림
7. 실내 위치가 부정확한 곳(지하)에서 자리가 안 잡히는지(정확도 100m 초과면 안 잡음)

### S9. 위젯 [떠나기] (8단계)
1. 홈 화면에 위젯 추가 → 오른쪽에 [떠나기]
2. 앱 완전 종료 상태에서 [떠나기] → 앱이 열리며 토스트 한 번
3. 앱 백그라운드 상태에서 [떠나기] → 토스트 한 번
4. 2번 직후 최근 앱 목록에서 앱을 다시 열기 → **토스트가 또 뜨면 실패**
5. 위 adb 위조 명령 → 아무 일도 없어야 정상
6. 체크리스트를 바꾼 직후 바로 [떠나기] → 정상 동작 (위젯이 다시 그려진 직후 탭)

### S10. 자기 전 정리 (5장)
1. 진단 → 예약된 알림에 `nightly-check-날짜` 6개 + `nightly-check-tail` (오늘 또는 내일부터)
2. 이전 버전에서 업데이트 설치한 기기라면 옛 `nightly-check`(날짜 없음)·`day-before-alert`·`feedback-alert`가 **없어야** 한다
3. **외출한 날**: 정리 시각에 착장 피드백 버튼 3개가 붙은 알림
4. **하루 종일 집에 있던 날** (집 Wi-Fi 등록, 앱을 종료하지 않음): 다음 외출에 비 예보·일정 준비물·그날만 항목이 있으면
   "다음 외출에 챙길 게 있어요"(버튼 없음), 없으면 알림 없음
   - 알림이 피드백 포함으로 왔다면: 진단 "외출 흔적"의 집 Wi-Fi 관찰 시각 사이가 2시간을 넘었는지 확인 (백그라운드 확인이 제조사 배터리 최적화로 밀린 것)
5. 정리 시각을 자정 이후(00:30)로 바꾸고 3·4 반복 — 어느 날 외출을 보는지 맞는지

### S11. 배터리
하루 평소처럼 쓴 뒤 설정 → 배터리 → 앱별 사용량에서 아맞다 비율. 위치 '항상 허용' + 집 밖 알림 켬 / 끔 두 날 비교.
배터리 최적화를 "제한 없음"으로 바꾼 날과도 비교해 S10-4의 관찰 간격이 달라지는지 본다.

## 5. 결과가 오면

- 실패·관찰 항목은 재설계 문서 9장 해당 단계의 "실기기에서 확인할 것" 옆에 결과와 대책을 적는다.
- 판정 규칙을 바꿔야 하면 `decide.ts`·`awayPlace.ts`·`nightlyRules.ts` 테스트부터 고친다 (규칙은 테스트로 고정).
- Play 백그라운드 위치 신고 시연 영상은 S2-2(공개 안내 → 권한 화면) + S3 첫 줄(앱을 닫은 채 알림)로 만든다 (legal/google-play-data-safety.ko.md 7장).
