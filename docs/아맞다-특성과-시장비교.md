## 1. 한 줄 정의

**아맞다는 "무엇을 챙길지"를 사람이 적기 전에 조건에서 먼저 꺼내고, "집을 나서는 순간"에 아직 안 챙긴 것만 짧게 알려주는 외출 준비 앱이다.**

> 기존 도구는 **기억해 낸 것을 붙잡아 주고**, 아맞다는 **기억해 낼 거리가 있다는 사실을 먼저 알려준다.**

## 2. 아맞다만의 특성

### 2.1 목록의 출처가 다르다 — 사람이 적지 않아도 생긴다 ★★★

체크리스트는 매일 네 출처에서 자동으로 조립된다.

| 출처 | 예시 |
|---|---|
| 날씨 (기상청·에어코리아) | 비 예보 → 우산, 미세먼지 나쁨 → 마스크, 폭염 → 물병 |
| 오늘 일정 (캘린더) | "팀 회의" → 출근 목적 → 노트북·명함·충전기 |
| 요일 루틴 | 월·수·금 → 헬스장 카드 |
| 오늘만 추가 | 사용자가 직접 (음성 입력 가능) |

사용자는 **떠올리는 대신 확인**만 한다(제품 원칙 2). 할일·리마인더 앱 8종이 모두 "사용자가 적은 것만" 알리는 것과 정반대다(`D-3` 3장).

### 2.2 알리는 순간이 다르다 — 시각이 아니라 "나가는 순간" ★★

- 출발 30분 전 알림, 그리고 **집 Wi-Fi를 벗어나는 순간** 알림이 있다. Wi-Fi 이탈 알림은 아직 안 챙긴 항목만, 최대 3개를 보여준다.
- 감시는 출발 시각 전후에만 동작하고(배터리 보호), 하루 1회만 알린다.
- 앱을 열지 않아도 홈 위젯과 잠금화면 상태 알림으로 "출발 시각 + 아직 안 챙긴 것 한 줄"을 볼 수 있다(Android).

> 이 축은 **혼자서는 차별점이 못 된다.** "장소를 떠날 때 알림"은 Apple 미리알림과 삼성 리마인더에 이미 무료로 있다. 2.1과 결합할 때, 즉 **알릴 내용이 자동으로 채워져 있을 때** 비로소 의미가 생긴다.

### 2.3 기준이 사람마다 다르다 — 개인 학습 ★★ (방어력의 원천)

| 학습 | 동작 |
|---|---|
| 체감온도 Δt | 처음 고른 민감도(기준값)와 저녁 피드백(학습값)을 **분리 저장**한다. 민감도를 다시 골라도 그동안 쌓인 학습이 사라지지 않는다 |
| 자주 까먹는 항목 | 집을 나설 때 체크 안 된 항목을 기록하고, 최근 7일에 2번 이상 놓친 항목에 "이번 주 N번 놓침" 뱃지를 단다 |
| 일정 키워드 | AI가 해석한 일정을 사용자가 수락하면 키워드로 승격된다. 다음부터는 AI 없이 인식한다 |

기능 목록은 복사할 수 있지만, **"이 사람에게 12도는 추운 날인지"는 그 사람이 몇 주간 남긴 응답으로만 생긴다.**

### 2.4 적게 말한다 — 표시 예산 원칙

- "늘리는 것은 앱이 아는 것이고, 줄이는 것은 사용자가 보는 것이다"([표시 계층 확장 구상](표시계층-확장-구상.md)).
- 알림은 미체크 항목만 최대 3개, 광고는 넣지 않는다(제품 원칙 4).
- 자동 판단은 전부 사용자가 덮어쓸 수 있다. 목적 수동 변경, 자동 항목 영구 끄기가 가능하다(제품 원칙 5).

### 2.5 AI를 쓰되, AI에 기대지 않는다 — 비용 0 개인화

| 방식 | 비용 | 앱의 외부 전송 | 상태 |
|---|---|---|---|
| **템플릿 개인화** — 사용자가 구독 중인 AI 앱(ChatGPT·Claude·Gemini)과 대화한 결과를 붙여넣음 | **0** | **없음** | 구현 |
| 일정 해석 (선택, 본인 API 키) — 키워드에 안 걸리는 일정만 | 1회 약 $0.00008 (추정), 하루 최대 3회 | 일정 **제목만**, 사전 동의 후 | 구현, 실호출 미검증 |

- 핵심 판단(체크리스트·알림)은 AI가 꺼져 있어도 똑같이 동작한다.
- AI 결과는 키워드·루틴 같은 **로컬 규칙으로 저장**되므로, 쓸수록 AI 호출이 줄어든다.
- 템플릿 개인화는 2.3의 약점인 **"초기 데이터 공백"**을 첫날부터 메운다.

### 2.6 계정도 서버도 없다 — 프라이버시 구조

- 회원가입 없음, 자체 서버 없음, 광고·분석 SDK 없음.
- 캘린더 일정은 **기기에도 저장하지 않는다.** AI 결과 캐시도 제목 원문 대신 해시로 저장한다.
- 외부 통신은 공공데이터 API뿐이고, 그것도 좌표 대신 격자번호·시도명만 보낸다. 예외는 사용자가 동의하고 켠 AI 기능뿐이다.

### 2.7 만들지 않는 것을 정해두었다

| 안 만드는 것 | 대신 |
|---|---|
| 길안내·경로 엔진 | 카카오맵·네이버지도로 **딥링크** 위임 |
| 범용 할일 관리·협업 | Todoist·TickTick의 영역 |
| 분실물 위치 추적 | AirTag·SmartTag의 영역 (3.3) |
| 옷 코디 추천 | 옷차림 앱의 영역. 아맞다는 체감온도와 "들고 갈 것"만 다룸 |

## 3. 시장 비교

### 3.1 한눈에 보기

| 특성 | 할일·리마인더 앱 (기본 앱 포함 8종) | 옷차림 앱 (웨더핏 등 4종) | 분실 방지 태그 (AirTag·SmartTag) | 여행 짐 싸기 (PackPoint) | **아맞다** |
|---|---|---|---|---|---|
| **무엇을 알리나** | 사용자가 **적은 것** | **입을 옷** | **태그 붙인 물건**의 위치 | 여행 1건의 짐 목록 | 날씨·일정·요일에서 나온 **들고 갈 것** |
| **목록의 출처** | 사람 | 기온 → 옷 규칙 | 해당 없음 | 목적지 날씨 + 활동 → 목록 | 날씨 + 일정 + 요일 + 사람 |
| **언제** | 사용자가 건 시각·장소 | 앱을 열 때 | **낯선 장소**에 두고 떠날 때 | 짐 쌀 때 | 출발 전 + **집을 나서는 순간** |
| **빈도** | 수시 | 매일 | 상시 | **여행 때만** | **매일** |
| **개인화** | 사용자가 적은 내용 | 같은 기온 = 같은 답 | — | 성별·여행 유형 정도 | 체감 Δt·놓침 이력·키워드 학습 |
| **추가 하드웨어** | 없음 | 없음 | **물건마다 태그** | 없음 | 없음 |
| **비용** | 무료 (장소 알림이 유료인 앱도 있음) | 무료 위주 | 태그 구매 | 무료 + 프리미엄 | 무료 (AI는 선택) |

### 3.2 할일·리마인더 앱 — 가장 가까운 경쟁자 (`D-3`)

- 8종(잊지마 할일, To-Do List, Todoist, MS To Do, Google Tasks, TickTick, 삼성 리마인더, Apple 미리알림)의 **"무엇을 알릴지" 칸이 전부 같다**: 사용자가 적은 것.
- 이 산업은 "앱은 시키지 않은 일을 하지 않는다"는 원칙을 지킨다. 그래서 틀릴 위험을 지지 않는 대신, **떠올리지 못한 것은 다루지 못한다.** 아맞다는 이 선을 의도적으로 넘는다. 그 대가로 지는 정확도 리스크는 4장에서 다룬다.
- 장소 알림은 기본 앱에 무료로 있지만 존재감이 약하다. Google은 Keep에서 장소 알림을 없애기까지 했다. 기능이 아니라 **알릴 내용이 비어 있어서** 안 쓰인다는 것이 아맞다의 가설이다(필드 검증 대상).

### 3.3 분실 방지 태그 — 같은 문제, 다른 지점

- **Apple "두고 가면 알림"(Notify When Left Behind):** iOS 15 이상. AirTag나 Apple 기기를 **낯선 장소**에 두고 떠나면 알린다. 집 같은 장소는 제외 목록에 넣을 수 있다.
- **삼성 "Notify when left behind"(SmartThings Find):** Galaxy Buds·Watch·S Pen Pro·SmartTag가 대상이다. 안전 장소(예: 집)로 설정하면 그곳에서 멀어져도 알리지 않는다.
- **겹치지 않는 이유**
  1. **태그를 붙인 물건만** 안다. 우산·서류·도시락처럼 그날그날 달라지는 물건은 대상이 아니다.
  2. 구조적으로 **"밖에 두고 오는 것"**을 잡는 도구다. **집에 두고 나가는 것**은 집을 안전 장소로 두는 순간 알림이 오지 않는다.
  3. 아맞다가 잡으려는 것은 **"집에서 나갈 때 안 챙긴 것"**이다. 두 도구는 경쟁이 아니라 보완 관계이고, 지갑·열쇠처럼 태그를 붙일 만한 물건은 태그가 더 확실하다.

### 3.4 옷차림 앱 (`D-1`)

- 핏프티, 웨더핏, 옷차림표, 날씨돌. 날씨를 **"무엇을 입을까"**로 번역한다.
- **"무엇을 들고 나갈까"는 다루지 않고**, 같은 기온에는 모두에게 같은 답을 준다.
- 아맞다는 옷 코디를 하지 않는다. 체감온도를 **개인 보정**해서 보여주고, 들고 갈 것을 맡는다.

### 3.5 여행 짐 싸기 앱 (PackPoint) — "조건 → 목록"의 선례

- 목적지, 날짜, 활동을 입력하면 목적지 예보를 반영해 짐 목록을 만든다. 비 예보면 우산을 넣는 식이다.
- **"조건에서 목록이 나온다"는 발상 자체는 아맞다만의 것이 아니다.** 이 점은 정직하게 인정해야 한다.
- 차이는 이렇다.

| | PackPoint | 아맞다 |
|---|---|---|
| 단위 | 여행 1건 (사용자가 입력) | 매일 (자동) |
| 입력 | 목적지·날짜·활동을 직접 입력 | 캘린더와 날씨를 앱이 읽음 |
| 알림 | 짐 쌀 때 앱을 열어 확인 | 집을 나서는 순간 |
| 개인화 | 여행 유형 수준 | 체감 Δt, 놓침 이력 학습 |

> 따라서 아맞다의 차별점을 정확히 쓰면 **"조건 → 목록"이 아니라 "매일, 입력 없이, 나가는 순간까지"**다.

## 4. 약점과 리스크 (정직하게)

| 리스크 | 내용 | 대응 |
|---|---|---|
| **기본 앱이 따라 하면** | 조건 → 항목 번역은 OS 사업자가 못 할 일이 아니다 | 방어선은 기능이 아니라 **개인 기준의 누적**(2.3). 시간이 필요하다 |
| **틀린 항목 → 알림 피로** | 시키지 않은 항목을 꺼내는 순간 틀릴 위험을 앱이 진다 | 표시 예산(최대 3개), 영구 끄기, 수락·거절, 근거 뱃지("09:00 '팀 회의' 연동됨") |
| **초기 데이터 공백** | 학습은 기록이 쌓여야 작동한다 | **템플릿 개인화**로 첫날 루틴·키워드를 채운다(2.5) |
| **장소 알림의 존재** | "떠날 때 알림"은 무료로 이미 있다 | 2.2를 단독 차별점으로 내세우지 않는다 |
| **조건 → 목록의 선례** | PackPoint | 차별점을 "매일·무입력·나가는 순간"으로 좁혀서 말한다 |
| **검증 상태** | 실기기 QA 미완. iOS 위젯 보류. AI 실호출 미검증 | [출시 전 현황](제품-정의서.md) 7장 |
| **필드 증거 없음** | "놓친 게 적을 생각을 못 한 것인가"가 미확인 | RID 과제 인터뷰(`D-3` 9장 4번)로 검증 예정 |

## 5. 포지셔닝 한 문장 (후보)

> **"오늘 들고 나갈 것을, 적지 않아도, 현관에서."**

- **적지 않아도** — 할일 앱과의 차이 (2.1)
- **들고 나갈 것** — 옷차림 앱·분실 태그와의 차이 (3.3, 3.4)
- **현관에서** — 매일, 나가는 순간 (2.2). PackPoint와의 차이 (3.5)
