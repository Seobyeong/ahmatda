# 비서 방향 — 기능 아이디어 모음

> 기준일: 2026-10-07 / 상태: **아이디어 단계 (확정 아님)**
> 관련 문서: [경로 기억 설계](경로-기억-설계.md), [제품 정의서](제품-정의서.md), [표시 계층 확장 구상](표시계층-확장-구상.md)

"외출하는 하루를 맡기는 비서" 방향에서 나올 수 있는 기능을 모았다. 실제로 넣을지는 아래 기준으로 거른다.

**거르는 기준**
1. **이미 아는 데이터로 판단할 수 있는가.** 새 입력을 요구하면 원칙 2(확인만 한다)와 부딪힌다.
2. **표시 예산을 지키는가.** 평소엔 조용하고 평소와 다를 때만 말해야 한다. 늘리는 것은 앱이 아는 것, 줄이는 것은 사용자가 보는 것.
3. **지도 앱, 캘린더 앱이 이미 하는 일이 아닌가.**

## ⭐ 우선 추천 5가지

이미 있는 데이터와 구조를 재사용하고, 다른 앱이 하지 않는 판단이다.

### 1. 외출 시간 전체의 날씨 변화로 챙길 것 판단
- **무엇:** 출발 시각 하나가 아니라 **나가 있는 시간 전체**(출발 → 일정 중 → 귀가)의 예보를 본다.
  - 일정 중에 비가 시작되면 → 우산
  - 오후에 기온이 크게 떨어지면 → 겉옷 ("나갈 땐 18°C, 귀가할 땐 9°C")
  - 나갈 땐 비가 오다가 그치면 → 우산을 **두고 올 위험**이 크다 (2번과 연결)
- **근거 데이터:** 첫 일정 시작 ~ 마지막 일정 종료(캘린더) × 시간대별 예보(이미 있는 5구간 타임라인).
- **나가 있는 동안 예보가 바뀌는 경우:** 예보는 하루 8번 갱신된다. 외출 중 새 예보에서 비가 새로 잡히면 "3시부터 비가 와요"라고 알린다. 백그라운드 조회가 제때 안 돌 수 있다는 한계는 경로 기억 설계 6장과 같다.
- **어느 위치의 날씨인가:** 지금은 **현재 위치** 예보만 본다. 경로 기억 2단계에서 목적지 좌표가 생기면 **일정 장소의 예보**를 따로 볼 수 있다 (집은 맑고 목적지는 비).
- **비용:** 없음. 기존 데이터 조합.
- **단계:** 시간대 판단은 (a)에서 바로 가능. 목적지 예보는 경로 등록 이후.

### 2. 두고 오기 방지 — 나갈 때 가져간 것 다시 챙기기
- **무엇:** 일정이 끝날 즈음 "카페에 노트북 충전기 두고 오지 마세요"라고 알린다. 아침에 체크한 항목 중 꺼내 쓸 만한 것(충전기, 우산, 텀블러)만 고른다.
- **왜 중요한가:** 데스크리서치에서 유실물 통계는 "안 챙기고 나온 것"이 아니라 **"두고 내린·두고 온 것"** 이었다. 그 지점을 직접 겨냥한다.
- **근거 데이터:** 아침 체크리스트 + 일정 종료 시각 + 우산은 날씨(비가 그쳤으면 더 잘 잊는다).
- **비용:** 없음. 로컬 알림.
- **주의:** 매번 울리면 소음이 된다. 꺼내 쓰는 물건이 있는 날만 알린다.

### 3. 하루 마무리 질문을 한 번에 묶기
- **무엇:** 귀가(홈 Wi-Fi 재연결)할 때 질문을 **한 번에** 묻는다. "추웠어요/적당했어요/더웠어요" + "늦었어요/딱 맞았어요/일찍 왔어요" + "안 챙겨서 아쉬웠던 것".
- **왜:** 학습할 축이 늘수록 질문 알림도 늘어난다. 묶지 않으면 비서가 아니라 설문 앱이 된다.
- **근거 데이터:** 기존 Wi-Fi 감지 (이탈 → 재연결로 확장).
- **비용:** 없음.

### 4. 잠금화면·홈 위젯 한 줄 — ✅ Android 구현 (2026-10-07), iOS 보류
- **구현:** Android 홈 위젯(`modules/ahmatda-widget`, 로컬 Expo 모듈 + RemoteViews) "08:15 출발 / 우산 · 노트북 외 1개". 잠금화면은 Android에 폰 잠금화면 위젯이 사실상 없어서, 출발 알림을 **감시 창 동안 고정되는 상태 알림**으로 바꿔 대신했다 (집을 나서거나 창이 끝나면 사라짐). 표시 내용은 플랫폼 공용 순수 함수 `buildDepartureSnapshot`.
- **iOS 보류 이유:** `expo-widgets`(v57)는 iOS 전용이고 prebuild(CNG) 전제인데, 이 프로젝트는 iOS 네이티브를 손으로 고친 bare 구조다. Apple Developer 계정과 macOS가 없어 빌드·검증도 불가능하다. 준비되면 같은 스냅샷으로 `accessoryRectangular`(잠금화면)와 `systemSmall` 위젯을 붙인다.

- **무엇:** "08:12 출발 · 우산 · 472번 9분 후". 앱을 열지 않아도 보인다.
- **왜:** 제품 정의서의 문제 2번 "정작 나갈 때 앱을 열지 않는다"에 대한 가장 직접적인 답이다. 표시 계층 구상의 첫 단계(폰 안의 작은 표시)이기도 하다.
- **비용:** iOS 위젯·Live Activity와 Android 위젯은 네이티브 작업이 필요하다. Expo SDK 57에서 지원 방식은 **미확인**이라 v57 문서 확인부터 해야 한다.
- **주의:** iOS는 macOS 없이 빌드·검증이 불가능하다.

### 5. 날씨·요일별 이동 시간 보정
- **무엇:** 비 오는 날, 월요일 아침은 평소보다 몇 분 더 걸리는지 학습해서 출발 시각에 더한다.
- **근거 데이터:** 도착 피드백(경로 기억 4단계)을 날씨·요일 조건으로 나눠 쌓는다. 체감온도 Δt처럼 공개 데이터 × 개인 계수 구조.
- **비용:** 없음. 데이터가 쌓이는 데 시간이 걸린다.
- **단계:** 경로 기억 4단계(자동 보정) 이후.

### 2-1. 하차 직전 "챙기세요" 알림 (사용자 제안, 2026-10-07)
- **무엇:** 대중교통으로 이동할 때 **내릴 역·정류장의 전 역**에 도착하면 "곧 내려요 — 우산, 노트북 가방 챙기세요"라고 알린다. 유실물이 실제로 많이 생기는 지점(두고 내림)을 정확히 겨냥한다.
- **참고:** 카카오맵은 2018년부터 위치 기반 **승하차 알림**을 제공한다 (길찾기 → 종 아이콘). 그래서 "내리세요" 알림 자체는 차별점이 아니다. 차별점은 **무엇을 챙겨야 하는지**(아침에 가져 나온 물건, 날씨)를 아는 쪽이 아맞다라는 점이다.
- **구현 방식 비교:**

| 방식 | 어떻게 | 필요한 것 | 정확도 | 판단 |
|---|---|---|---|---|
| **A. 시간 기반** | 실제 출발(Wi-Fi 이탈) + 정류장까지 도보 + 대기(실시간 도착정보) + 학습한 탑승 시간 → **예상 하차 2분 전** 로컬 알림 | 추가 권한 없음 | ± 몇 분. 정체가 심한 날엔 어긋남 | 먼저 |
| **B. 정류장 지오펜스** | 하차 전 정류장 좌표(TAGO 정류소 API의 좌표)에 반경을 걸어, 들어가면 알림 | **백그라운드 '항상 허용' 위치 권한**, 개인정보 문서 개정, 스토어 심사 소명 | 버스는 높음. **지하철은 지하라 GPS가 약해 불안정** | 선택형 옵트인으로 나중에 |
| C. 버스 실시간 위치 추적 | TAGO 버스위치정보로 내가 탄 차량을 따라감 | 어느 차량에 탔는지 알아야 함 + 계속 조회(서버 필요) | 높음 | 비용 대비 과함. 보류 |

- **추천:** A로 시작한다. 경로 기억(정류장·노선·탑승 시간)이 있어야 가능하므로 **경로 기억 3~4단계 이후**다. 지하철은 시간표 기반인 A가 오히려 B보다 낫다.
- **결정 필요:** B를 하려면 "외출 중 위치를 쓰지 않는다"는 기존 판단(경로 기억 설계 5장)을 **이동 구간 한정으로 완화**해야 한다. 계속 기록하는 게 아니라 정류장 한 곳에 지오펜스만 거는 방식이지만, 권한 요구 수준은 같다.
- **알림에 넣을 것:** 아침에 체크한 항목 중 **꺼내 쓰는 물건**(우산, 충전기, 텀블러, 노트북)만. 그리고 비가 그쳤다면 우산을 맨 앞에.

## 하지 않을 것

| 하지 않을 것 | 이유 |
|---|---|
| 자체 지도·길안내·환승 안내 | 지도 앱이 압도적. 딥링크로 위임 (경로 기억 설계 1장) |
| 실시간 도착정보 화면 복제 | 지도 앱에 이미 있음. 아맞다는 숫자를 보여주는 게 아니라 "지금 나가세요"로 **판단**만 전달 |
| 캘린더 편집·일정 관리 | 캘린더 앱의 일. 읽기만 한다 |
| 외출 중 위치 계속 기록 | '항상 허용' 권한, 배터리, 심사, 개인정보 문서 재작성 비용 (경로 기억 설계 5장) |
| 메시지 자동 전송 | 오발송 위험. 초안까지만 만든다 |
| 교통카드 잔액 관리 | 읽을 데이터가 없어서 수동 입력이 필요함 → 원칙 2 위배 |

## 공통 주의: 알림 개수

위 아이디어를 다 넣으면 하루 알림이 준비 시작 → 출발 → 직전 보정 → 두고 오기 → 귀가 질문 → 전날 브리핑으로 **6개 이상**이 된다. 유일한 실패 모드는 "다 넣었더니 아무것도 안 읽힌다"이다.

**제안 규칙:** 하루 기본 알림은 **출발 1개 + 마무리 1개**로 고정한다. 나머지는 **평소와 다를 때만** 출발 알림에 한 줄로 얹거나 따로 울린다 (비 오는 귀가, 버스 지연, 두고 올 물건이 있는 날).
