# 비서 방향 — 기능 아이디어 모음

> 기준일: 2026-10-07 / 상태: **아이디어 단계 (확정 아님)**
> 관련 문서: [경로 기억 설계](경로-기억-설계.md), [제품 정의서](제품-정의서.md), [표시 계층 확장 구상](표시계층-확장-구상.md)

"외출하는 하루를 맡기는 비서" 방향에서 나올 수 있는 기능을 모았다. 실제로 넣을지는 아래 기준으로 거른다.

**거르는 기준**
1. **이미 아는 데이터로 판단할 수 있는가.** 새 입력을 요구하면 원칙 2(확인만 한다)와 부딪힌다.
2. **표시 예산을 지키는가.** 평소엔 조용하고 평소와 다를 때만 말해야 한다. 늘리는 것은 앱이 아는 것, 줄이는 것은 사용자가 보는 것.
3. **지도 앱, 캘린더 앱이 이미 하는 일이 아닌가.**

---

## ⭐ 우선 추천 5가지

이미 있는 데이터와 구조를 재사용하고, 다른 앱이 하지 않는 판단이다.

### 1. 귀가 시점 날씨로 챙길 것 판단
- **무엇:** 나갈 땐 맑아도 **돌아오는 시각**에 비가 오면 우산을 챙기게 한다. 지금은 "오늘 비 예보"를 하루 단위로 본다.
- **근거 데이터:** 일정 종료 시각(캘린더) × 시간대별 예보(이미 있는 5구간 타임라인).
- **비용:** 없음. 기존 데이터 조합.
- **단계:** (a)에서 바로 가능.

### 2. 두고 오기 방지 — 나갈 때 가져간 것 다시 챙기기
- **무엇:** 일정이 끝날 즈음 "카페에 노트북 충전기 두고 오지 마세요"라고 알린다. 아침에 체크한 항목 중 꺼내 쓸 만한 것(충전기, 우산, 텀블러)만 고른다.
- **왜 중요한가:** 데스크리서치에서 유실물 통계는 "안 챙기고 나온 것"이 아니라 **"두고 내린·두고 온 것"** 이었다. 그 지점을 직접 겨냥한다.
- **근거 데이터:** 아침 체크리스트 + 일정 종료 시각 + 우산은 날씨(비가 그쳤으면 더 잘 잊는다).
- **비용:** 없음. 로컬 알림.
- **주의:** 매번 울리면 소음이 된다. 꺼내 쓰는 물건이 있는 날만 알린다.

### 3. 하루 마무리 질문을 한 번에 묶기
- **무엇:** 귀가(홈 Wi-Fi 재연결)할 때 질문을 **한 번에** 묻는다. "추웠어요/적당했어요/더웠어요" + "늦었어요/딱 맞았어요/일찍 왔어요" + "안 챙겨서 아쉬웠던 것".
- **왜:** 학습할 축이 늘수록 질문 알림도 늘어난다. 묶지 않으면 비서가 아니라 설문 앱이 된다.
- **근거 데이터:** 기존 Wi-Fi 감지 (이탈 → 재연결로 확장).
- **비용:** 없음.

### 4. 잠금화면·홈 위젯 한 줄
- **무엇:** "08:12 출발 · 우산 · 472번 9분 후". 앱을 열지 않아도 보인다.
- **왜:** 제품 정의서의 문제 2번 "정작 나갈 때 앱을 열지 않는다"에 대한 가장 직접적인 답이다. 표시 계층 구상의 첫 단계(폰 안의 작은 표시)이기도 하다.
- **비용:** iOS 위젯·Live Activity와 Android 위젯은 네이티브 작업이 필요하다. Expo SDK 57에서 지원 방식은 **미확인**이라 v57 문서 확인부터 해야 한다.
- **주의:** iOS는 macOS 없이 빌드·검증이 불가능하다.

### 5. 날씨·요일별 이동 시간 보정
- **무엇:** 비 오는 날, 월요일 아침은 평소보다 몇 분 더 걸리는지 학습해서 출발 시각에 더한다.
- **근거 데이터:** 도착 피드백(경로 기억 4단계)을 날씨·요일 조건으로 나눠 쌓는다. 체감온도 Δt처럼 공개 데이터 × 개인 계수 구조.
- **비용:** 없음. 데이터가 쌓이는 데 시간이 걸린다.
- **단계:** 경로 기억 4단계(자동 보정) 이후.

## 시간 축 (언제 나갈까)

| 아이디어 | 내용 | 데이터·비용 | 판단 |
|---|---|---|---|
| 준비 시작 알림 | 출발 시각에서 "평소 준비 시간"을 역산해 "지금 씻기 시작하면 맞아요" | 앱을 처음 연 시각 ~ Wi-Fi 이탈 시각으로 준비 시간 학습. 비용 없음 | 좋음. 다만 아침 알림이 하나 더 늘어난다 → 출발 알림과 합치는 방식 검토 |
| 늦을 것 같을 때 메시지 초안 | 계획보다 밀리면 "10분 정도 늦을 것 같아요" 문자 초안을 공유 시트로 띄움 | 연락처 권한 불필요(공유 시트). 비용 없음 | 좋음. **자동 전송은 하지 않는다** — 반드시 사용자가 보냄 |
| 막차·첫차 경고 | 늦게 끝나는 일정이면 "막차 23:42, 23:20엔 나오세요" | TAGO 노선 정보에 첫차·막차 필드가 있는지 **미확인** | 확인 후 판단 |
| 일정 지연 시 재계산 | 앞 일정이 길어지면 다음 일정 출발 시각 다시 계산 | 범위 (b). 현재 위치 필요 → 포그라운드 위치만 쓸지 결정 필요 | (b) 단계에서 |

| 아이디어 | 내용 | 데이터·비용 | 판단 |
|---|---|---|---|
| 장소별 준비물 | 등록한 경로·장소에 준비물을 묶음 ("헬스장" → 운동복). 지금은 일정 제목 키워드로만 목적을 감지 | 경로 기억 2단계의 Route에 붙이면 됨 | 좋음. 목적 감지보다 정확 |
| 배터리 체크 | 폰 배터리가 낮고 외출이 길면 보조배터리 추가 | `expo-battery` 등 (v57 확인 필요). 비용 없음 | 좋음. 제품 정의서의 "기기 상태"와 연결 |
| 긴 외출 판단 | 일정이 저녁까지 이어지면 겉옷·충전기 추가 | 캘린더 마지막 일정 종료 시각 | 좋음. 1번과 묶어서 구현 가능 |

## 하루 전체 (범위 b·c)

| 아이디어 | 내용 | 판단 |
|---|---|---|
| 전날 밤 브리핑 | 내일 첫 일정, 출발 시각, 날씨, 챙길 것을 한 번에. 기존 "전날 알림"(`scheduleDayBeforeAlert`)의 확장 | (c)의 가장 가벼운 입구. 추천 |
| 전날 같이 계획 짜기 | 일정 사이 이동과 순서를 함께 정리 | 범위가 커서 브리핑 반응을 본 뒤 |
| 일정 사이 빈 시간 제안 | "1시간 비어요, 근처 카페…" | ❌ 표시 예산 위반 위험, 비서가 아니라 추천 앱이 됨. 보류 |

## 하지 않을 것

| 하지 않을 것 | 이유 |
|---|---|
| 자체 지도·길안내·환승 안내 | 지도 앱이 압도적. 딥링크로 위임 (경로 기억 설계 1장) |
| 실시간 도착정보 화면 복제 | 지도 앱에 이미 있음. 아맞다는 숫자를 보여주는 게 아니라 "지금 나가세요"로 **판단**만 전달 |
| 캘린더 편집·일정 관리 | 캘린더 앱의 일. 읽기만 한다 |
| 외출 중 위치 계속 기록 | '항상 허용' 권한, 배터리, 심사, 개인정보 문서 재작성 비용 (경로 기억 설계 5장) |
| 메시지 자동 전송 | 오발송 위험. 초안까지만 만든다 |
| 교통카드 잔액 관리 | 읽을 데이터가 없어서 수동 입력이 필요함 → 원칙 2 위배 |

## 공통 주의: 알림 개수

위 아이디어를 다 넣으면 하루 알림이 준비 시작 → 출발 → 직전 보정 → 두고 오기 → 귀가 질문 → 전날 브리핑으로 **6개 이상**이 된다. 유일한 실패 모드는 "다 넣었더니 아무것도 안 읽힌다"이다.

**제안 규칙:** 하루 기본 알림은 **출발 1개 + 마무리 1개**로 고정한다. 나머지는 **평소와 다를 때만** 출발 알림에 한 줄로 얹거나 따로 울린다 (비 오는 귀가, 버스 지연, 두고 올 물건이 있는 날).
