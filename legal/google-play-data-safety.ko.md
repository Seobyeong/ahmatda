# Google Play 데이터 안전성 설문지 답변 초안

## 0. 요약 답변 (Play Console 첫 화면 질문들)

- **앱이 사용자 데이터를 수집합니까?** 예 — 단, 전부 기기 내부(로컬)에만
  저장됩니다.
- **앱이 사용자 데이터를 제3자와 공유합니까?** 예 — 위치 정보(변환된
  격자좌표/시도명)를 대한민국 공공데이터포털 API와 공유. 그 외 항목은 공유 없음.
- **데이터가 전송 중 암호화됩니까(in transit)?** 예 — 기상청/에어코리아 API
  호출은 HTTPS를 사용합니다. (실제 axios 호출 URL이 https:// 인지 코드에서
  재확인 필요)
- **사용자가 데이터 삭제를 요청할 방법을 제공합니까?** 예 — 앱을 삭제하면
  기기 내 모든 데이터가 함께 삭제됩니다(별도 서버 계정이 없어 삭제 요청 절차
  자체가 불필요). 앱 내 설정 화면에서 개별 항목도 직접 삭제 가능.

## 1. 위치 정보 (Location)

| 세부 항목 | 답변 |
|---|---|
| 대략적 위치(Approximate location) | 수집함 |
| 정확한 위치(Precise location) | 수집함 (expo-location으로 GPS 좌표 조회) |
| 수집 목적 | 앱 기능(날씨/미세먼지 조회), 개인 맞춤(해당 없음) |
| 기기 외부로 전송됨? | 예, 공유함(제3자: 대한민국 정부 공공데이터포털 API) — 원본 좌표는 전송하지 않고, 변환한 기상청 격자좌표(nx,ny)·시도명만 전송되지만 보수적으로 "공유함"으로 표시하기로 확정(2026-07-06) |
| 선택 사항(Optional) 여부 | 선택 가능 — 위치 권한을 거부해도 앱의 다른 기능은 동작함 |
| 처리 방식 | Ephemeral(일시적) — 좌표 자체를 기기/서버 어디에도 저장하지 않고 조회 즉시 변환·폐기 |

**백그라운드 위치(외출 감지 재설계, 2026-11-04 추가) — 답변은 위와 같게 유지.**
집 반경·머문 장소 지오펜스, 집 위치 좌표·지금 머무는 자리 좌표 저장은 전부 기기 안에서만
처리되고 기기 밖으로 나가지 않는다. Play 정의상 "수집(Collect)"은 *기기 밖으로 전송*하는 것이고,
"기기 안에서만 처리하고 밖으로 보내지 않는 데이터는 공개하지 않아도 된다"(Data safety 도움말
answer/10787469, 2026-11-04 확인). 그래서 위 날씨 조회 답변 외에 추가 항목은 없다.
다만 **백그라운드 위치 권한 신고서**는 데이터 안전성과 별개로 필요하다 → 아래 7장.

## 2. 개인 정보 (Personal info)

이름, 이메일, 전화번호, 주소, 사용자 ID 등 — **수집하지 않음** (회원가입/로그인
기능 없음).

## 3. 캘린더 (Calendar)

- react-native-calendar-events로 오늘 일정의 제목·시각·장소를 읽음.
- **앱이 기기 외부로 전송하지 않음** — 앱 실행 중 메모리에서만 참조, 저장하지 않음.
- 예외: 이용자가 [길찾기]를 누르면 장소 문자열만 검색어로 담아 카카오맵(웹 링크)
  또는 네이버지도 앱을 연다. [판단 필요: 이용자 조작에 의한 다른 앱 호출이 Play
  "공유(Shared)" 정의에서 제외되는 "사용자가 시작한 작업"에 해당하는지 Play 고객센터
  문서로 확인 후 답변 확정]
- Google Play 공식 데이터 유형 목록에 전용 **"Calendar"** 카테고리("Calendar
  events" — 이벤트, 이벤트 메모, 참석자 정보)가 별도로 존재함. 이 카테고리로
  분류하고 "수집함(앱 실행 중 일시적 참조, 저장·공유 없음)"으로 답변.
- **[선택] AI 일정 해석 (AI 기능 출시 시 갱신 필요):** 이용자가 동의하고 켜면,
  키워드로 알 수 없는 일정의 **제목만** 이용자 본인의 API 키로 Anthropic(Claude API,
  미국)에 전송. Play 기준 "공유(Shared)"에 해당할 가능성이 높음 → Calendar 항목을
  "수집함·공유함 / 선택사항 / 목적: 앱 기능"으로 갱신하고, 상단 "제3자와 공유" 답변에도
  추가. [판단 필요: 이용자 본인 키로 보내는 구조가 Play "공유" 예외(사용자가 시작한
  작업 등)에 해당하는지 확인]
- Google Play AI 생성 콘텐츠 정책: 챗봇·이미지 생성 같은 생성형 AI 앱이 대상이고
  "AI를 기능으로 쓰는 생산성 앱"은 제외로 안내돼 있어 해당하지 않을 가능성이 높음.
  그래도 앱에 제안마다 거절 버튼과 설정의 "이상한 제안 신고하기"(메일)를 두었다.

## 4. 앱 활동 / 앱 정보 및 성능 (App activity / App info and performance)

- 크래시 로그, 진단 데이터, 분석 데이터: **수집하지 않음** (Sentry 등 크래시
  리포팅 미도입 상태 — 도입 시 이 문서와 개인정보처리방침의 "5. 개인정보처리
  위탁" 항목을 함께 갱신해야 함).

## 5. 기기 또는 기타 ID (Device or other identifiers)

- 홈 Wi-Fi BSSID(MAC 주소 성격의 식별자)를 기기 내부(AsyncStorage)에만 저장.
- **기기 외부로 전송되지 않음.**
- Play Console에 "기기 ID" 관련 문항이 있다면 "수집함(기기 내부 저장, 공유
  안 함)"으로 답변.

## 5-1. 건강 및 피트니스 (Health and fitness > Fitness info)

- Android 활동 인식(ACTIVITY_RECOGNITION)으로 걷기·달리기·자전거·탈것·정지가 **시작된 시각**만
  기기 안(SharedPreferences)에 기록하고, 외출 판정·머묾 판정에 쓴 뒤 3~24시간 안에 지운다.
- **기기 밖으로 전송하지 않음 → "수집하지 않음"**(Play 정의상 기기 안에서만 처리한 데이터는 공개
  대상 아님). Fitness info("운동 또는 기타 신체 활동") 문항이 보이면 "수집 안 함"으로 답한다.
- 나중에 이 시각이나 판정 결과를 서버·분석 도구로 보내게 되면 Fitness info를 "수집함"으로 바꾼다.

## 6. 데이터 보안 관행 체크리스트

- [x] 사용자가 데이터 삭제를 요청할 수 있음 (앱 삭제 / 앱 내 설정)
- [x] 전송 중 데이터 암호화(HTTPS)
- [ ] 독립적인 보안 검토를 받았는지 — [사용자 확인 필요, 통상 소규모 앱은 해당 없음]
- [x] Google Play의 Families 정책 대상 아님 (아동 대상 앱 아님 — 필요 시 확인)

## 7. 백그라운드 위치 권한 신고서 (앱 콘텐츠 > 민감한 앱 권한 > 위치 권한)

근거: Play 고객센터 answer/9799150 (2026-11-04 확인). 요점:
- **백그라운드 위치가 필요한 기능은 하나만 신고**한다 — 여러 개를 적으면 거절된다.
  아맞다는 집 반경 이탈과 머문 장소 이탈 두 경로가 있지만 같은 기능이므로 **하나로** 적는다:
  > **떠날 때 안 챙긴 물건 알림** — 이용자가 집이나 오래 머문 곳을 떠나는 순간을 감지해, 아직 안
  > 챙긴(또는 그 자리에서 꺼내 쓴) 물건을 알린다. 떠나는 순간에 휴대폰을 보고 있지 않으므로 앱이
  > 화면에 없을 때도 위치(지오펜스 이탈)를 받아야 하며, 앱의 핵심 목적("아 맞다"를 막는 것)이 이것이다.
- 앱 안 공개 안내: 런타임 요청 전에 표시 — `BACKGROUND_LOCATION_DISCLOSURE`
  (src/services/departure/homeGeofence.ts). "위치" 단어, "앱을 닫았거나 사용하지 않을 때도", 기능 이름이
  들어 있다. **같은 내용을 스토어 설명과 웹사이트에도 실어야 한다** — 아직 안 함.
- 시연 영상(30초 이하, YouTube 권장): ① 설정에서 '위치 항상 허용' → 공개 안내 → 시스템 권한 화면
  ② 집 위치 등록 ③ 앱을 닫은 채 집 반경을 벗어나면 알림이 오는 장면. [실기기 촬영 필요]
- 기능이 거절되면: 백그라운드 위치 없이도 걷기 + Wi-Fi로 외출 판정은 동작한다(권한 저하, 외출-감지-재설계
  3장 표). '집 밖에서 떠날 때 알림'만 쓸 수 없게 된다.

## 최종 제출 전 체크리스트

1. Play Console 실제 문항과 이 문서의 매핑이 최신인지 대조 (문항 구성이 자주 바뀜)
2. Sentry 등 크래시 리포팅을 도입하면 이 문서의 "4. 앱 활동" 항목을 반드시 갱신
3. 백그라운드 위치 신고서 제출 + 시연 영상, 스토어 설명에 공개 안내 문구 추가 (7장)
4. 활동 인식 권한: Play에 별도 신고서는 없지만, 개인정보처리방침에 항목이 있는지 확인 (반영됨)
